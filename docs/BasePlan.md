## 1. 项目总览与设计范式

### 1.1 项目目标

从原始音频（WAV/MP3）+ 难度 + 判定线事件轨（可选）出发，**端到端生成可玩的 Phigros 谱面（RPEJSON）**。

Phigros 与 4K 下落式（osu!mania / DDR）的本质区别，决定了本项目的一切技术选择：

| 维度 | 4K VSRG | **Phigros** |
|------|---------|------------|
| 空间 | 4 条静止离散轨道 | **判定线局部系 2 维**：`positionX` 连续 + `side`（哪一侧） |
| 屏幕方向 | 恒定自上而下 | **任意方向**——由判定线自身的 move/rotate 事件轨决定 |
| 舞台对象 | 无 | **判定线是一等公民**：多线（中位 30 条）、带完整事件轨的动画对象 |
| 音符类型 | TAP/HOLD/… | Tap / Drag / Hold / Flick（+ `above` / `isFake`） |

### 1.2 核心范式

```
音频 → MERT 隐式理解
     → 判定线局部系多线强度场 λ_k(τ, positionX, side, type | 线事件轨, 难度)
       （τ = **拍相对时间坐标**，beat-aligned，1/48 拍；见 §3.2.4）
     → 掩码补全迭代并行解码
     → 非齐次泊松 NLL 训练
     → 强度场解码为离散谱面 → 合法性后处理 → RPEJSON
```

三个不可动摇的选择（详见 [RFC-0029](decisions/RFC-0029-phigros-continuous-chart-generation.md) §2/§3）：

1. **在判定线局部系建模**（非屏幕系）。局部系是谱面的**原生存储系**：判定线锚点为原点、线本身为 X 轴、锚点朝向为 +Y；音符恒沿局部 Y 轴下落。"任意方向"只是同一局部系经 `rotateEvents` 旋转后的屏幕表现，**不是第三种侧别**。
2. **多判定线在 v1 即引入**（非单线）。实测 `judgeLineList` 中位 **30** 条，单线假设会丢掉 95%+ 的结构。
3. **多线共用一个 x 网格**。`positionX` 是 RPE 舞台系的**绝对** x 坐标（实现即 `position_x / 675`），**与判定线无关**，无 per-line 缩放 → 多线无需任何坐标校正。

### 1.3 一个必须先说清的事实：谱面生成不是转录

STRUM（arXiv 2605.12135）实测：**人类谱面事件只有 89.0% 落在音频 onset ±100ms 内**（n=39,136 鼓事件）。

这条事实决定了三件事：

- 训练目标**不能**默认为「音频 onset 的狄拉克和」；
- 以音频为输入、以人类谱为目标，recall 存在一个**与音频无关的上界**；
- 本任务的正确定位是**创造性诠释（interpretation）**，而非转录（transcription）——人类 mapper 有约 11% 的落点不在 onset 上，那正是"创作"发生的地方。

评估必须因此报告 per-song 全局 offset 搜索下的一组数 + 不搜索的一组数（见 §9 与 RFC-0029 §5.1）。

### 1.4 与 v2.x 的关系（本次修宪改了什么）

| 维度 | v2.x | **v3.0** |
|------|------|---------|
| 目标游戏 | osu!mania 4K VSRG | **Phigros** |
| 谱面表示 | VQ-VAE 小节码本 → BPE/event token 序列（RFC-0028） | **判定线局部系多线强度场** |
| 生成主干 | AR Transformer 逐 token | **掩码补全 Encoder-Decoder（迭代并行）** |
| 目标函数 | 交叉熵 / 回归 | **非齐次泊松过程 NLL** |
| 全局规划 | Stage1 密度规划（段级回归） | **取消该层**（段级均值池化是结构性信息瓶颈，且不需要） |
| 音频编码 | MERT-v1-330M + Adapter | **不变**（帧率口径已修正为 75Hz） |

> ⚠️ **范式变更的动因澄清**：v2.x 的 Stage1 在万级数据上 loss 不降，其**直接原因是一个实现 bug**（MERT 真实帧率 75Hz，代码三处硬编码 25Hz，差 3×），**不是范式本身的判决**。该 bug 已修复并制度化门禁（§9）。范式变更的真实依据是**目标游戏变更**。详见 [POSTMORTEM-2026-08-05](POSTMORTEM-2026-08-05-frame-rate-misalignment.md)。

## 2. 系统架构总览

```
┌──────────────────────────────────────────────────────────────────────┐
│ 输入层（极简）                                                        │
│  ① 音频(WAV/MP3)   ② 难度   ③ 判定线事件轨（可选，条件输入）          │
└───────────────────────────┬──────────────────────────────────────────┘
                            ▼
┌──────────────────────────────────────────────────────────────────────┐
│ Stage 0  音频理解                                                     │
│   MERT-v1-330M（冻结，24kHz）+ 可训练 LoRA Adapter                    │
│   → audio_emb [B, T, 1024]，帧率 = 24000/320 = 75Hz（**派生量**）    │
└───────────────────────────┬──────────────────────────────────────────┘
                            ▼
┌──────────────────────────────────────────────────────────────────────┐
│ Stage 1  强度场生成（掩码补全 Encoder-Decoder）                       │
│   Encoder：audio_emb + 判定线事件轨 → 音乐/舞台上下文                 │
│   Decoder：输入被遮盖的场，预测 λ_k(t, x, s, c)，k = 1..K             │
│   条件：难度 / 线事件轨 / （可选）参考风格                             │
└───────────────────────────┬──────────────────────────────────────────┘
                            ▼
┌──────────────────────────────────────────────────────────────────────┐
│ Stage 2  解码与导出                                                   │
│   ① 强度场 → 离散事件（v0: find_peaks；原则性: Ogata thinning）       │
│   ② 合法性/可玩性后处理（同刻上限、Hold 区间、**跨线几何冲突**）       │
│   ③ 写 RPEJSON                                                        │
└──────────────────────────────────────────────────────────────────────┘
```

**训练目标**（泊松 NLL，对 K 条线求和）：

```
L = - Σ_n log λ_{k(n)}(e_n)  +  Σ_{k=1..K} ∫∫∫ λ_k(t,x,s) dt dx ds
      └ 事件处强度必须高 ┘      └ 全域积分必须低（防"到处乱亮"）┘
```

**关键性质**：note 分配到哪条判定线**不需要**额外的分类损失——它是 K 个强度场**竞争**的自然结果。这一点极其重要，因为实测显示 note 分布极度不均（最忙的一条线独占中位 **73%** 的 note），任何"均匀 softmax 分配"的假设都是错的。

## 3. 逐模块技术选型详解

### 3.1 Stage 0：音频理解 —— **MERT-v1-330M + LoRA Adapter**（沿用 v2.x）

| 属性 | 规格 |
|------|------|
| 主干 | `m-a-p/MERT-v1-330M`（24 层，hidden = **1024**，全部冻结） |
| 采样率 | **24000 Hz**（官方 preprocessor 要求） |
| 特征提取器 | 7 层卷积，`conv_stride = [5,2,2,2,2,2,2]`，累乘 **320** |
| **输出帧率** | `24000 / 320 = 75 Hz` —— **派生量，禁止硬编码** |
| Adapter | LoRA（RFC-0003），注入 attention q/v |
| 长音频 | 5s 窗 / 1s 重叠 + 重叠区按帧率对齐平均 |

> **帧率是派生量，不是超参**。v2.x 曾把它硬编码为 25 Hz（真值 75 Hz，差 3×），在 mock 的掩护下存活到万级数据规模。详见 [POSTMORTEM-2026-08-05](POSTMORTEM-2026-08-05-frame-rate-misalignment.md)。

### 3.2 谱面表示：**判定线局部系多线标记点过程**

#### 3.2.1 为什么不是别的

| 被否决的方案 | 否决理由 |
|-------------|---------|
| **VQ-VAE 小节码本**（RFC-0028 已退役） | 本质是"小节级最近邻检索重组"：新曲节奏型几乎必然是训练集未见的精确组合，只能落到最近 code，**信息损失不可逆** |
| **纯离散 event token + AR** | 保留为**对照臂 B3/B4**，不作主线：逐 token 解码慢且误差累积，无法利用事件间强共现（同时音、连续 Hold） |
| **朴素高斯热图 + BCE** | 稀疏目标下**必然塌到"全 0"解**——正是本项目"loss 不降"症状的同构形态。EBC-ZIP（arXiv 2506.19955）明确指出 MSE/MAE 在零值主导目标上 *biased toward predicting low or zero values* |
| **屏幕系 $(t,x,y)$ 表征** | 判定线旋转时同一物理 note 在屏幕系中会移动 → 目标分布非平稳，且丢失"线的哪一侧"语义 |

#### 3.2.2 事件空间与标记

```
chart  := ( {line_1 .. line_K}, {note_1 .. note_N} )     K >= 1（v1 不限制）
line_k := { moveX(t), moveY(t), rotate(t), alpha(t), speed(t) [+ extended 第5层] }
note_n := { line_id, t, positionX, side, type ∈ {tap, drag, hold, flick},
            hold_time, speed, is_fake }
```

- **`side` 是硬自由度**：官方格式用 `notesAbove` / `notesBelow` **两个数组**分别存储；`above == 1` → 正面，**其余值** → 背面（实现必须写 `above == 1 ? FRONT : BACK`，**不得当布尔解析**）。两侧几何上是**关于判定线 X 轴的 Y 镜像**。
- **实测标记分布**：Tap 52–63% / Drag 20–31% / Hold 10–11% / Flick 6–7%；**背面仅 2.4–3.0%** → 强不平衡，评估必须**单独报背面 recall**。
- v1 **不含** Tempo 事件（BPM 来自谱面，作为条件）；**不手编**手型/chord 语义（让模型自己学）。

#### 3.2.3 多判定线（v1 即引入）

实测（n=196）：`judgeLineList` 中位 **30** 条（p25=24 / p75=52 / max=82 / min=2）。

- 强度场为 **λ_k(t,x,s,c)，k = 1..K**，K 随谱面变化 → 属「可变数量对象的条件生成」；
- 实现须为**共享权重 + 每条线一个 line embedding（作 query）**，不得把 K 硬编码进输出层；
- **判定线不可互换**（各有独立事件轨）→ 排序不变性不成立，`line_id` 不是对称标签；
- 解码器必须能**同时看到全部 K 条线的场**（"哪条线该接这个音"取决于所有线的当前位姿）；
- **实测 note 极度集中**：只有中位 58% 的线带 note，**最忙的一条线独占中位 73%** 的 note；存在「25 条线、1578 个 note 全在 1 条线上」与「56 条线、最忙仅 23%」两种极端 → **`line_id` 不能当作均匀 softmax 分类**；
- 另：26% 的谱面含 `father` 嵌套线；23/23 有非空 `extended`。

#### 3.2.4 网格与单位（红线 7：一切派生）

| 量 | 值 | 依据 |
|----|----|------|
| `positionX` 单位 | RPE 舞台系 x 坐标单位，全域 **1350** = 舞台宽 | A 级：prpr `parse/rpe.rs:588` 即 `position_x / 675` |
| 可见范围 | **[−675, 675]**（**可见边界，非合法值域**） | 格式与参考实现**均无钳位** → 解析只统计、**不钳位**（否则违法红线 3） |
| 网格桶宽 | **`Δx = RPE_STAGE_WIDTH / N`**，默认 **N = 128 → 10.546875** | 必须派生；须补 N ∈ {64,128,256,512} 消融 + 共格碰撞统计 |
| `lineLength` | 判定线局部系**半长**（默认 6.0 ⟹ 半长 3 倍屏宽）；**与 positionX 无关** | A 级：prpr `core/line.rs:251` |
| 速度单位 | 1 速度单位 = **120.23 RPE-y 单位/秒** | A 级：prpr `SPEED_RATIO`；与 wiki「120 px/s」差 0.19% |
| **时间网格** | **beat-aligned**：τ 以 **1/48 拍**为基本格，随 BPM 变化 | GOCT 消融 8 分音符 **87.9% vs 70.0%**（未对齐且输出会漂移）；**三方独立收敛到 1/48 拍** |

> **⚠️ beat-aligned 的数学改写必须限定在 `field/` 内（决策者约束）**：积分测度从 `dt` 变为 `J(τ)dτ`（`J(τ) = dt/dτ` 由 `BPMList` 精确给出）。契约层 `PhigrosNote.t` **仍用秒**（RFC-0001 结论不变）；秒 ↔ τ 换算只在 `field/` 内实现且必须派生；下游不得各自再实现一套换算。**须有一条契约测试断言「场网格 ↔ 秒」往返无损（覆盖多 BPM 段）**，否则 beat-aligned 会变成下一个 25 Hz。

> **⚠️ 越界不得钳位**：实测 12674 个 note 全部落在 [−675, 675] 且多为 0.125 的整数倍，但**存在携带任意浮点的谱**（实测最小间隔 0.32）→ **只能做区间校验，不能做整除校验**。

### 3.3 生成主干：**掩码补全 Encoder-Decoder**（主选）

- **Encoder** 吃 `audio_emb` + 判定线事件轨；长上下文用**滑动窗口自注意力 + 周期性全局层**；
- **Decoder** 以完形填空方式工作：训练时遮盖目标场的部分片段，预测被遮盖位置；推理时**迭代并行**填充；
- **必须显式提供 mask 通道**（否则模型无法区分"此处无 note"与"此处被遮盖"）；
- **按事件遮盖，不按帧遮盖**：note 极稀疏，按帧随机遮盖时邻帧几乎必然含相同事件，模型可以"抄邻居"而不学任何东西。

**对照臂（RFC-0029 §5.2，全部必须实现）**：B1 热图+focal（**文献主流，正式消融臂而非稻草人**）｜B2 主线｜B3 离散 token+AR（GOCT 配置）｜**B4 自回归上界臂**｜B5 掩码离散扩散｜B6 解码策略消融。

> **「掩码补全」与「离散扩散」在训练目标上不是两件事**：absorbing-state 扩散的 NELBO 等价于**按时间步加权的掩码交叉熵**（arXiv 2510.03289 式 (10)）。消融**必须指明对照层级**（训练目标 vs 采样策略），否则不可解释。
> **反方证据不可忽略**：arXiv 2510.03289《Why Mask Diffusion does not Work》指出并行采样缺乏理论保证，最稳策略仍可能是自回归 → **B4 不可省**。

### 3.4 目标函数：**非齐次泊松过程 NLL**

```
L = - SUM_n log λ_{k(n)}(e_n)  +  SUM_k INTEGRAL λ_k
```

| 问题 | 朴素 BCE / 热图 | **泊松 NLL** |
|------|----------------|-------------|
| 稀疏性（正样本 ~1e-3） | 塌到"全 0"解 | 积分项惩罚全 0 解 |
| 音符数量 | 由阈值超参决定 | 由强度场积分隐式决定（泊松计数） |
| 概率语义 | 逐 cell Bernoulli，多高斯叠加后全图积分远大于 1，不是分布 | λ 是强度，NLL 是合法似然 |
| 同时多音 | 逐 cell 独立 | 点过程天然支持 |

**两条积分实现路径，必须互相校验**：

1. **网格数值积分**（与强度场同网格，分辨率显式声明）；
2. **累积强度参数化**：Omi et al., NeurIPS 2019（arXiv 1905.09690）参数化 Λ(t) 再求导，积分项可**精确**计算。

`field/` 模块须同时实现两条路径并以一致性测试对齐——这本身又是一道契约门禁。

> **硬约束**：积分必须与强度场在**同一离散网格**上进行。否则会以另一种形式重现"单位错配"类 bug。
> **热图 focal 与泊松 NLL 不兼容**：CornerNet/CenterNet 的目标 y 是**未归一化**高斯（积分值不等于事件数），与点过程不在同一测度 → B1 是独立消融臂，损失不得混用。
> **G3 常数基线**：`λ = N/|Ω|`（**不是** `λ = 0`——后者泊松 NLL = +∞，应写成契约断言）。

### 3.5 条件注入

| 条件 | 方式 | 状态 |
|------|------|------|
| 难度 | 可学习嵌入，AdaLN / 前缀 | 必做 |
| **判定线事件轨** | 编码为舞台上下文，cross-attention | 必做（Q2 决议：**条件化**，v1 不做联合生成） |
| 音频 | cross-attention | 必做 |
| 参考风格 | 检索（RAG） | Phase 3 待重估，RFC-0029 未涉及 |

### 3.6 解码与导出

1. **强度场 → 离散事件**：v0 用峰值检测 + 阈值（`find_peaks`），**原则性做法是 Ogata (1981) thinning**（从 λ 直接采样）；两者须做**对照臂**。
2. **合法性后处理**（只做红线校验与钳位，**不得改变模型的落点分配逻辑**，红线 3）：同刻按键上限、Hold 区间合法性、越界、**跨线几何冲突**（两条线在屏幕空间重叠/交叉时）。
3. **写 RPEJSON**。

> 必须在**原始时间域（秒）**评估，不得在帧索引域评估。

### 3.7 明确不做的事

- 不与判定线**联合生成**线事件轨（v1 只条件化）；
- 不做 Flow Matching 蒸馏（Phase 3 再议）；
- 不做 DPO 偏好对齐 / RAG 风格检索（Phase 3 待重估）；
- 不追求推理 <2s/首（先要质量，再要速度）。

## 4. 训练数据策略与来源

### 4.1 数据源（实测，2026-08-05）

| 项 | 值 |
|----|----|
| 入口 | **Phira 官方 API** `GET https://api.phira.cn/chart` —— 实测 **count = 9649** |
| 关键坑 | 响应键是 `results`（非官方文档写的 `result`）；`pageNum` 上限 **30**；**无按定数过滤参数** |
| 带宽优化 | 谱面包 CDN **支持 HTTP Range** → 可只抓中央目录 + 单条目，**省约 90%**（全量直抓约 **76GB**，推断） |
| 格式分布 | **RPE 97.2%** / PEC 2.5% / 官谱 JSON 0%（n=283 抽样；深页 PEC 升至 4.4%） |

### 4.2 数据形态与三类静默陷阱

单包（n=196 实测）= `info.yml`(100%) + 谱面文件 + **音频(100%)** + 曲绘(100%) + `info.txt`(97%)。中位 6.56MB。

1. **文件后缀不可信**：实测 chart id 7039 的 `24432296.json` **内容是 PEC 文本**。
2. **谱面文件名不可猜**：`info.yml.format` 恒为 `null`，且 **196/196 张都不叫 `chart.json`** → **必须读 `info.yml.chart` 定位**。
3. **note `type` 数字在两套格式中含义不同**（RPE：1 Tap / 2 Hold / 3 Flick / 4 Drag）→ 混用不分流会静默全员错位。

### 4.3 数据流水线

```
API 枚举（322 页元数据）→ Range 抓包 → 解压 → info.yml 定位谱面
   → 按内容（而非后缀）判定格式 → RPEJSON 解析 → Chart IR
   → beat→秒 换算（1T = 1.875/bpm 秒，A 级确证）
   → 质检（区间校验、越界统计、量纲断言）
   → MERT 特征离线提取（按 set 去冗余）→ (audio, chart) 训练对
```

## 6. 风险评估与缓解

| 编号 | 风险 | 影响 | 缓解 |
|:---:|------|------|------|
| **R-1** | MERT 对特定曲风表征不足 | 生成适配度下降 | 保留 Adapter 可训练；必要时解冻后 6 层（需 RFC） |
| **R-2** | **数据合规**：唯一万级数据源未授予训练权 | 已由决策者承担风险；**残余影响 = 不得发布权重** | §4.4 的裁决与四条硬约束；**发布权重前必须重新裁定** |
| **R-3** | 社区谱面质量参差，模型学到坏习惯 | 输出手感差 | 质检 + 社区信号加权；Phase 3 DPO 兜底 |
| **R-4** | **稀疏目标塌陷**（"loss 不降"的同构形态） | 训练不收敛 | 泊松 NLL（积分项惩罚全 0）+ **G1-G4 门禁 + B1/B2 对照** |

| **R-7** | **物理常量/单位漂移**（25Hz 类） | 静默数据损坏 | 红线 7：一切派生 + 断言，**契约级测试进默认 CI** |
| **R-8** | 跨线几何冲突不可玩 | 谱面不可玩 | 后处理含跨线几何检查（只校验不改创意，红线 3） |

## 8. 选型决策矩阵

| 模块 | 主选 | 备选/对照 | 否决 | 核心理由 |
|------|------|----------|------|---------|
| 音频编码 | **MERT-v1-330M + LoRA** | MuQ / MusicFM（未来对比） | Qwen2-Audio | 音乐专用、轻量、层次表征好 |
| 谱面表示 | **判定线局部系多线强度场** | 离散 event token（B3） | VQ-VAE 码本；朴素热图 | 无量化损失；保留精确事件；避免稀疏塌陷 |
| 生成主干 | **掩码补全 Enc-Dec** | AR（B4 上界）；掩码离散扩散（B5） | 纯逐 token AR 作主线 | 并行 + 双向上下文；事件间强共现 |
| 目标函数 | **非齐次泊松 NLL** | — | 朴素 BCE / MSE 热图 | 稀疏下不塌；数量可控；合法似然 |
| 解码 | **Ogata thinning** | `find_peaks`（v0） | 纯阈值 | 从 λ 直接采样的原则性做法 |
| 判定线运动 | **条件化输入** | 联合生成（未来） | 忽略线运动 | 难度与观感大量来自线运动 |
| 全局规划层 | **取消** | — | 段级密度回归 | 均值池化是结构性信息瓶颈，且不需要 |

## 9. 工程红线与健全性门禁

**四道门禁（`beatmorph/infra/sanity.py`，任何新模型/新范式在扩大数据规模前必须全绿）**：

| 门禁 | 判据 | 抓什么 |
|------|------|--------|
| **G1 单 batch 过拟合** | 在 1-4 个样本上能把 loss 打到接近 0 | 通路断、梯度断、loss 用错 |
| **G2 打乱标签对照** | shuffle 目标后 loss **必须显著变差** | 输入对目标零信息 |
| **G3 常数基线** | 模型 loss 必须显著优于 `λ = N/|Ω|` | 模型其实什么都没学到 |
| **G4 契约断言** | 帧率/形状等物理量由 config 派生并断言 | 单位/帧率漂移 |

**评估协议要点**（完整见 RFC-0029 §5）：

- F1 **双容差报告**（±20ms 对 DDC / ±50ms 对 GenéLive!）+ **单独报全谱相位偏移** + 背面 recall；
- **NLL 只作校准指标**，不得作质量分数——ChartGenEval 实测 perplexity 在"常见图案重写"下**下降 37%**、self-similarity 在"循环塌缩"下**上升 62%**，两个指标都会朝错误方向移动；
- **"响应音乐（能量相关性）"是探索性指标**，不得作模型选择主判据；
- 贪心一对一匹配；**未匹配的生成事件留在分母**；按谱平均与 micro 平均都报；
- 人评采用 MIREX 2026 三段式（算法 → 约 5 名 mapper 专家评 → 社区混入人类谱盲测）。

## 结语

v3.0 确立了 **"音乐自监督理解 + 判定线局部系标记点过程 + 掩码补全 + 泊松似然"** 的技术基座。

它与此前版本最大的不同，不在于换了哪个模型，而在于**把"我们不知道什么"也写进了文档**：

- 单位与几何有 **A 级源码证据**，也有 **D1-D10 明确的未决项**；
- 数据源有 **实测数字**，也有 **16 条存疑**与**未做的全库统计**；
- 文献有结论，也有 **18 条未核实项**与一条检索阴性结论的方法论警告；
- 已发生的错误（25 Hz）**留档并制度化成了门禁与红线**，而不是修掉了事。

> **本项目最大的历史教训**：一个没有测试覆盖的物理常量等价于一个未经声明的假设；而一个**被 mock 覆盖了**的物理常量，等价于一个被伪装成事实的假设。

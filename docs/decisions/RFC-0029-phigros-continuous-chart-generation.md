## 0. 前提澄清（重要：不要把两件事混为一谈）

本议案的触发是「Stage1 在万级数据上 loss 完全不可下降」，但 postmortem 已**证明直接原因是一个实现 bug**：MERT-v1-330M 真实帧率 75 Hz（24000/320），代码三处硬编码 25 Hz 且提取路径不降采样，导致"秒→帧"映射整体错 3×。

因此：

- **范式变更不以该 bug 为依据。** 该 bug 已单独修复，并新增 G1-G4 四道门禁（`beatmorph/infra/sanity.py`）防复发。
- 范式变更的真实依据是**决策者的目标变更**：从 osu!mania 4K 转向 **Phigros**。
- 两者独立：修 bug 不改变范式结论，换范式也不会自动修好 bug（新范式同样依赖帧率这一物理量）。

## 2. Phigros 问题形式化（本议案核心）

### 2.1 note 的空间状态是 2 维，不是 1 维

参考文档（`newplan.md`）把谱面表示为 `(T, W, C)`，其中 `W` 是"判定线位置维度"的单一轴。**这不足够。**

Phigros 中一条 note 的空间状态至少是：

- `positionX`：沿判定线局部 x 轴的位置（相对判定线中心的连续量）。**单位未查证**——不要假设 [-1,1]，见 §8.2 Q8；
- `side` ∈ {above, below}：**从判定线的哪一侧落向判定线**（格式字段 `above`）。

**决定性事实（决策者 2026-08-05 指出）：note 并非全部自上而下下落，可以从任意一个方向落进判定线。**

机制（已由格式调研逐条确证，见 [phigros-format.md §6.2](../knowledges/phigros-format.md)）：note 在**判定线局部系**中**恒沿局部 Y 轴**接近判定线；判定线本身由 `rotateEvents`（角度制，顺时针）旋转、由 `moveXEvents`/`moveYEvents` 平移；于是同一条物理 note 在**屏幕系**中的接近方向 = 局部 Y 轴经该时刻旋转角旋转后的方向，随事件轨连续变化 → 屏幕上可为任意角度。**「任意方向」不是第三种侧别，而是同一侧别经旋转后的屏幕表现。**

推论：
1. 单轴 `W` 表征**丢掉 `side`**。同一 `positionX`、相反 `side` 的两条 note 在屏幕上出现在线的两侧，**图案语义与打法完全不同**。丢掉它等于丢掉一个硬性自由度——官方格式为此专门用 `notesAbove` / `notesBelow` **两个数组**分别存储，可见侧别是格式级的一等维度。
2. 参考文档第 3.1 节的 "sigma_w 建议为谱面宽度的 2%-5%" 隐含了"位置是一维"的假设，需重写。
3. 屏幕系表征（`(t, x, y)`）看似"更自然"，但当判定线旋转时，同一条物理 note 在屏幕系中会移动——目标分布非平稳，且丢失"线的哪一侧"这一语义。**局部系才是谱面的原生存储系。**

### 2.2 判定线必须作为一等公民建模

Phigros 的难度与观感**大量来自判定线的运动**（旋转、位移、变速、消失）。只生成 note、把线固定成静止水平线，产出的不是 Phigros 谱面，而是一个退化的无轨道下落式谱面。因此必须三选一：

- **(a) 联合生成**：note 场 + 线事件轨一起预测；
- **(b) 条件化**：线事件轨作为输入条件（给定/引用/另一模块生成），只预测 note；
- **(c) 分层**：v1 只支持静止或简单运动的线，明确声明能力边界。

> 建议 v1 走 **(b)+(c)**：把线事件轨作为**条件输入**（数据里有，直接喂），先解 note 生成；待 note 侧站住后再上 (a) 做联合生成。

### 2.3 形式化

```
chart := ( {line_1..line_K}, {note_1..note_N} )            K ≥ 1（v1 不限制为 1）
line_k := { 事件轨: moveX(t)/moveY(t)/rotate(t)/alpha(t)/speed(t) [+extended 第5层] }
note_n := { line_id, t, positionX, side, type ∈ {tap,drag,hold,flick},
            hold_time, speed, is_fake }
```

即一张谱面是**判定线局部系上的标记点过程（marked point process）**的一次实现：
标记 = (line_id, positionX, side, type, hold_time, ...)。

> 判定线集合在 RPE 中是**固定的列表**（`judgeLineList`），即 K 在单张谱内恒定、跨谱可变；
> 线的「出现/消失」通过 alpha/speed 事件轨表达，而非增删列表项。

### 2.4 多判定线：v1 即引入（决策者 2026-08-05 决定）

**决策**：不把 v1 限制为单条主判定线，而是**在本阶段就引入多判定线机制**，让模型从数据中学习 note 在判定线之间如何分配。

这是本议案中**建模代价最高**的一条，必须写清后果：

1. **事件空间多出一个类别轴**：强度场从 λ(t,x,s,c) 变为 **λ_k(t,x,s,c)，k = 1..K**，K 随谱面变化（1 ~ 数十条）。
2. **输出规模可变**：这是「可变数量对象的条件生成」，与 DETR 类集合预测同构。可行做法是**共享权重 + 每条线一个 line embedding（作为 query）**，使网络自然支持任意 K；而不是把 K 硬编码进输出层。
3. **判定线不可互换**：每条线有自己的 move/rotate/alpha/speed 轨，因此 `line_id` 不是对称标签——排序不变性**不成立**，不能像集合预测那样随意匹配。线的身份由其在 `judgeLineList` 中的**索引 + 事件轨条件**共同确定。
4. **跨线交互必须可见**：不同线上的 note 可能同时出现，且两条线在屏幕上的相对位置随各自的运动连续变化——「哪条线该接这个音」取决于**所有线的当前位姿**。因此解码器必须能同时看到**全部 K 条线的场**（掩码补全的全局注意力天然满足这一点；若改成分线独立预测则会丢掉交互）。
5. **合法性与可玩性约束跨线**：两条线在屏幕空间可能重叠/交叉，此时同刻 note 的判定与可读性会变化。§5 的合法性指标必须包含**跨线几何检查**（而不只是单线内检查）。
6. **对损失的影响**：泊松 NLL 直接对 K 个场求和即可（`L = -Σ_n log λ_{k(n)}(e_n) + Σ_k ∫λ_k`），**不需要**为「分配到哪条线」另设分类损失——分配是强度场竞争的自然结果。这是点过程表述相对「先分类后回归」两阶段方案的实质优势。

7. **重大简化（源码级确证，2026-08-05）**：`positionX` **与判定线无关**——它不是相对线长的归一化量，而是 **RPE 舞台系的绝对 x 坐标**（实现即 `position_x / 675`，与 `moveXEvents` 同刻度；`lineLength` 只决定线本身的绘制长度，默认 6.0 ⟹ 半长 3 倍屏宽）。**因此所有判定线共用同一 x 网格**，v1 多线建模**无需任何 per-line 坐标校正**。见 [phigros-units-and-geometry.md §3/§4](../knowledges/phigros-units-and-geometry.md)。

8. **数据侧已核实（n=196 实测，2026-08-05）**：`judgeLineList` 中位 **30 条**（p25=24 / p75=52 / max=82 / min=2）→ **单线假设会丢掉 95%+ 的结构，v1 多线完全成立**。但 note 高度集中：中位只有 **58%** 的判定线带 note，**最忙的一条线独占中位 73% 的 note**；存在两种极端形态——「25 条线、1578 个 note 全在 1 条线上」与「56 条线、最忙仅 23%」。
   → **`line_id` 不能当作均匀 softmax 分类**（此结论为推断）。这正是点过程表述的价值：K 个强度场的**竞争**天然表达"某条线吃掉 73%"这种极度不均，无需额外的分配策略或重加权。
   - 另：26% 的谱面含 `father` 嵌套线；23/23 有非空 `extended`（第五层）。

**仍需在数据侧核实**：全库 K 分布（本轮 n=196 为抽样）、note 跨线分配的时序模式。

## 3. 表征与目标函数

### 3.1 强度场（替代参考文档的"高斯热图"）

把谱面表示成**强度场**：

```
λ_k(τ, x, s, c | audio, line_tracks[1..K], difficulty) ≥ 0      k = 1..K
   k: 判定线索引（见 §2.4；v1 不限制 K=1）
   τ: **拍相对时间坐标**（beat-aligned，Q15 决议）——以 **1/48 拍**为基本格，
      网格随 BPM 变化；τ ↔ 秒 的换算由谱面 `BPMList` 给出（见下方"数学代价"）
   x: positionX —— **单位已确证为 RPE 舞台坐标 x ∈ [-675, 675]**
      （KillKPA/Phigros Wiki「术语」页明确写出坐标系范围 [-675,675]×[-450,450]）
   s: side ∈ {above, below}（2）
   c: 类型通道（tap/drag/hold/flick + hold-end 标记）
```

> **时间网格 = beat-aligned（Q15 决议，2026-08-05）**：
> - **依据**：GOCT 消融实测未对齐会显著掉分（8 分音符 **87.9% vs 70.0%**），且未对齐模型的输出**随时间漂移**——与本项目已付过代价的失效模式同类；**三次独立工作各自独立收敛到 1/48 拍**（GOCT 的 hop、ITGPT 的 48 位置/拍、本项目 v2.x 的 POS 网格）。
> - **⚠️ 数学代价必须限定在 `field/` 内（决策者约束）**：积分测度从 `dt` 变为 `J(τ)dτ`，其中 `J(τ) = dt/dτ` 由 `BPMList` **精确给出**；Omi 的累积强度参数化相应改写为对 τ 积分。**该改写不得外溢**：
>   - 契约层 `PhigrosNote.t` **仍用秒**（RFC-0001 结论不变）；
>   - 秒 ↔ τ 的换算**只在 `field/` 内发生**，且必须由 `BPMList` 派生、**不得硬编码**；
>   - 下游（生成主干 / 解码 / 导出）只与 `field/` 暴露的场契约交互，**不得各自再实现一套时间换算**。
> - **必须有一条契约测试**断言"场网格 ↔ 秒"往返无损（用变速谱面覆盖多 BPM 段）——否则 beat-aligned 会变成下一个 25 Hz。

> **空间网格裁定（源码级确证后，2026-08-05）**：
> - `positionX` 单位 = **RPE 舞台系 x 坐标单位**，全域 1350 = 舞台宽（A 级：prpr `parse/rpe.rs:588` 即 `position_x / (RPE_WIDTH/2)`）。
> - 桶宽 **`Δx = RPE_STAGE_WIDTH / N`，默认 N = 128 → Δx = 10.546875 RPE-x 单位**（0.781% 舞台宽）。
> - **必须是派生常量**（红线 7）：代码里写 `RPE_STAGE_WIDTH / N`，**不得**写 `10.546875`。
> - **v1 不走连续回归**：`∫λ` 的「同网格」硬约束（§3.2）与门禁可验证性都要求离散网格。但**必须补做 N ∈ {64,128,256,512} 消融**，并先统计「同刻 + 同侧 + 同线的最小 |ΔpositionX|」共格碰撞率再定 N——否则 128 只是换了个魔数。
> - **越界不钳位**：±675 是**可见边界**而非合法值域（格式与参考实现均无校验）；解析阶段**只统计不钳位**（钳位会违反红线 3）。

### 3.2 目标函数：非齐次泊松过程精确 NLL

```
L = - Σ_k log λ(e_k)  +  ∫∫∫ λ(t,x,s) dt dx ds
      └ 事件处必须高   ┘   └ 全域积分必须低（防止到处乱亮）┘
```

**为什么不用朴素 BCE**（参考文档的选择）：

| 问题 | 朴素 BCE | 泊松 NLL |
|------|---------|---------|
| 稀疏性（正样本 ~1e-3） | 塌到"全 0"解——**精确复现本项目"loss 不降"的症状** | 积分项惩罚把 λ 压向 0 的全 0 解 |
| 音符数量 | 由阈值超参决定，不可控 | 由强度场积分隐式决定（泊松计数） |
| 概率语义 | 逐 cell Bernoulli，多个高斯叠加后全图积分 ≫ 1，不是分布 | λ 是强度，NLL 是合法似然 |
| 同时多音 | 逐 cell 独立，无联合语义 | 点过程天然支持 |

**硬约束**：积分项 `∫λ` 必须与强度场在**同一离散网格**上数值积分，且网格分辨率显式声明——否则会以另一种形式重现"单位错配"类 bug（见 §7）。

**∫λ 的正确工程解（文献支持）**：Omi et al., NeurIPS 2019（arXiv 1905.09690）参数化**累积强度 Λ(t)** 再求导得到 λ，使 `∫λ` 可**精确**计算、无需网格近似。本议案要求 `field/` 模块**同时实现**「网格数值积分」与「累积强度参数化」两条路径，并以一致性测试对齐（同一场上二者给出的 NLL 必须一致到给定容差）——这本身又是一道契约门禁。

**为什么朴素 BCE / 热图会塌**：EBC-ZIP（arXiv 2506.19955）明确指出 MSE/MAE 在零值主导的目标上 *biased toward predicting low or zero values*、*dominance of zero-valued regions weakens the supervisory signal*，其解法正是**泊松族 NLL**（零膨胀泊松）。音乐领域先例：Peeling & Li, JASA 2007（DOI 10.1121/1.2716156）。

**G3 常数基线可立即实现**：`λ ≡ N/|Ω|`（N = 事件数，|Ω| = 场体积），**不是 `λ ≡ 0`**——后者泊松 NLL = +∞，应写成契约断言。

**|Ω| 口径（2026-08-05 裁定）**：|Ω| = **全 K 条线测度之和**（**空线也计入**，因此空线是有成本的——这正是"最忙线独占 73%"能被自然表达的原因）。G3 基线 `N/|Ω|` 据此成立。评估阶段的"按谱归一化"是**报告口径**，与训练测度无关，二者不冲突。

**⚠️ 遮盖训练的重标定（plan 04 发现的定量缺陷，2026-08-05）**：若**只对被遮盖事件**计算事件项、而积分项仍覆盖全域，则最优 λ 会被**系统性缩放 (1−r)**（r = 遮盖率；r = 0.5 时欠计数约一半）。必须做 **Horvitz–Thompson 式 `1/(1−r)` 重标定**，并**同时保留 L_full（全事件项）作为校准口径**。

> **为什么不能退回"全事件项"训练**：若事件项覆盖全部事件，则"把输入复制到输出"是可行解——note 极稀疏时模型能直接抄未遮盖部分，学不到任何东西。这正是"**按事件遮盖**"存在的理由。故「只预测被遮盖区域 + HT 重标定」是自洽的组合，「全事件项」则与遮盖训练的目标冲突。

### 3.3 生成架构：掩码补全（保留参考文档的有效直觉）

参考文档"谱面生成更像翻译/补全而非逐 token 自回归"的直觉有依据（与 ITGPT、Beat-Aligned Spectrogram-to-Sequence 的路线谱系一致：谱面事件间存在强共现）。但需补三条：

1. **必须显式提供 mask 通道**，否则模型无法区分"此处无 note"与"此处被遮盖"。
2. **按事件遮盖而非按帧遮盖**：note 极稀疏，按帧随机遮盖时邻帧几乎必然含相同事件，模型可以"抄邻居"而不学任何东西。
3. 连续场不是唯一选择：保留精确离散事件 + **absorbing-state 离散扩散 / MaskGIT 式迭代解码**，同样拿到并行与双向上下文，且免掉热图量化损失。**真实选择轴是 (顺序 vs 迭代并行) × (序列似然 vs 点过程似然)。**
4. **「掩码补全」与「离散扩散」在训练目标上不是两件事**：absorbing-state 扩散的 NELBO 等价于**按时间步加权的掩码交叉熵**（arXiv 2510.03289 式 (10)）。因此 §5 的消融**必须指明对照层级**（比的是训练目标，还是采样/解码策略），否则"消融"不可解释。
5. **反方证据必须纳入**：arXiv 2510.03289《Why Mask Diffusion does not Work》指出并行采样缺乏理论保证，最稳策略仍可能是自回归。故 **AR 上界臂（B4，见 §5.2）不可省**。
6. **B3 与 B4 的边界（2026-08-05 裁定）**：两者字面都含"离散 token + AR"，但**目的不同、不可互相替代**，报告中必须分列：
   - **B3 = 文献对标臂**：复现 GOCT 的公开配置（hop = 1/48 beat、CE + label smoothing、±30ms），回答"我们相对**已发表工作**处于什么位置"；
   - **B4 = 严格上界臂**：在**同一数据、同一容量、同一训练条件**下训练一个自回归版本，回答"迭代并行解码相对顺序解码**损失了多少**"。

### 3.4 连续 → 离散的解码

参考文档交给 `scipy.find_peaks` + 阈值。该做法把难题从"生成"挪到"检测"，且不可微、超参敏感。本议案要求：

- 峰值/阈值检测必须与训练目标**同网格**；
- 必须在**原始时间域（秒）**评估，不得在帧索引域评估；
- 基线解码（find_peaks）可作 v0，但必须作为**消融项**而非终点；
- **原则性解码器**：从强度场采样事件的正确工具是 **Ogata (1981) thinning**（从 λ 直接采样），应作为 `find_peaks` 的**对照臂**而非替代品。
- **热图 focal 与泊松 NLL 不兼容**：CornerNet/CenterNet 的目标 y 是**未归一化**高斯（`∫y ≠ 事件数`），与点过程似然不在同一测度上。故 B1（热图 + focal）是**独立消融臂**，不能与 B2 混用损失。

## 5. 评估与实验设计（参考文档最薄弱处）

### 5.1 指标

- **事件级**（主判据）：F1 @ ±20ms（对齐 Dance Dance Convolution 口径）与 F1 @ ±50ms（对齐 GenéLive! 口径）**双报告**；`positionX` MAE；`side` 准确率；类型准确率。
- **协议细节**：贪心一对一匹配；**未匹配的生成事件留在分母**；按谱平均与 micro 平均**都报**；「固定解码规则」与「每谱最优」**两栏**，且两个范式用同一格式。
- **分解**：按时间组（含 12/24 三连）与按难度分解报告。
- **⚠️ 全谱相位偏移必须单独报**：STRUM（arXiv 2605.12135）实测**人类谱面事件只有 89.0% 落在音频 onset ±100ms 内**（n=39,136 鼓事件）。这意味着：
  1. 强度场的训练目标**不能**默认为「音频 onset 的狄拉克和」；
  2. 「以音频为输入、以人类谱为目标」的 recall 存在一个与音频无关的**上界**；
  3. 必须报告 per-song 全局 offset 搜索下的一组数 + 不搜索的一组数。
  > 更深一层的含义（应写进 BasePlan §1）：谱面生成**不是转录（transcription），而是创造性诠释**——人类 mapper 有 11% 的落点不在 onset 上。
- **⚠️ 结构级指标是探索性的**：ChartGenEval（arXiv 2607.12857）把「响应音乐（能量相关）」标为 **exploratory、无 held-out 证据**。故「密度曲线与音乐能量曲线相关性」**不得作模型选择主判据**。
- **⚠️ NLL 只能当校准指标**：ChartGenEval 实测 perplexity 在「常见图案重写」下**下降 37%**、self-similarity 在「循环塌缩」下**上升 62%**——似然与自相似度都会朝**错误方向**移动。泊松 NLL 用于概率校准与门禁，**不得当作质量分数**。
- **合法性**：物理约束合法率（同刻按键上限、Hold 区间合法性、**跨线几何冲突**、越界）。

### 5.2 基线与消融臂（全部必须实现，缺一不可）

| 臂 | 内容 | 为什么不可省 |
|----|------|-------------|
| **B1** | 热图 + focal loss | 文献主流做法，**必须是正式消融臂而非稻草人** |
| **B2** | **主线**：泊松 NLL 强度场 + 掩码补全 | 本议案主选 |
| **B3** | 离散 event token + 自回归 | 以 GOCT 配置为骨架（同源动机＝二分类不均衡；有公开权重；ITGPT 已给第三方数字 Max F1 0.7754） |
| **B4** | **自回归上界臂** | arXiv 2510.03289 对并行采样的质疑要求一个 AR 上界 |

采用 MIREX 2026 三段式：① 算法产出 → ② 约 5 名 mapper 专家评 *musical representation / creativity / gameplay* + humanity score → ③ **社区混入人类谱盲测**，令玩家指认哪张是人写的。

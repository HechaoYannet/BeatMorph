# RFC-0031 — τ 轴终点口径（`T` 取自哪个字段）

- 状态：提案 ｜ 提出日期：2026-09-27 ｜ 决定日期：（待裁定）
- 提出者：主会话（数据流水线 / 训练基础设施）
- 影响模块：plan 00（`PhigrosChart.duration_s()` 的语义与 `META.chartTime` 的地位）、
  plan 02（`data/dataset.py` 的 τ 轴终点、清单与特征缓存的依赖）、plan 03（§9-14）、
  plan 04（窗口长度与训练输入）、plan 07（门禁与训练前置）

## 背景

plan 03 §9-14 从立项起就写着「`T`（τ 轴长度）的终点口径**未查证**，不得凭猜实现」，
三个候选是 **`META.chartTime` / 最后一事件 / 音频时长**。当时的实现（plan 02 M11）选择了
`PhigrosChart.duration_s() = max(最后一事件, chartTime)`——一个**保守上界**——并把它标注为临时口径。

本轮（2026-09-27 第五轮）第一次把它**测量**出来，结论是：这不是边界情形，而是**语料级缺陷**。

### 实测事实（全库 8551 张，`data/processed/charts.jsonl` 的行级统计）

| 指标 | 实测值 |
|---|---|
| `time_span_s / audio_duration_s > 10` | **4452 张（52.2%）** |
| 该比值：中位 / p75 / p99 / 最大 | **52.8 / 382 / 2575 / 3 407 201** |
| `time_span_s`：中位 / p99 / 最大 | **7766 s（2.2 h） / 421 513 s / 7.49e8 s（≈23 年）** |
| `audio_duration_s`：中位 / p99 / 最大 | 151 s / 369 s / 1282 s |
| 分布形状 | **双峰**：47% 落在音频 1.1× 以内，53% 远超音频 |
| 有事件超出音频（`out_of_audio_window > 0`） | 228 张 |

样本：chart 27751 `chartTime=104 512.82` 而最后一个 note 在第 444 拍（220 BPM ⇒ 121 s）；
chart 26102 `chartTime=7.49e8` 而音频 220 s。`chartTime` **既不是秒也不是任何一致单位**，
各谱师工具写入的值不可作为时间轴的事实源。

### 后果（都在本轮实测过）

1. **数据集规模被虚增 98%**：train split 在旧口径下切出 **3361 万窗**，修复后 **634 952 窗**（94.1 窗/行）。
   多出来的全是**空窗**（无事件 + 音频整段越界补零）。全库索引因此要 **2.3 h** 才轮到第一个优化步。
2. **G1 假绿**：门禁的 G1 批抽到的正是这种空窗（实测 `K=2`、**0 事件**），
   报出 `loss 7819.5 -> 0.0014` 的 PASS，而**没有任何事件可过拟合**。
3. **G2 被伪造成「结构性失效」**：打乱臂在空窗上「把计数摊开」比真实臂「定位稀疏峰值」更容易，
   于是得到 `shuf/real = 0.835`（打乱**更好**），曾被判为控制设计不成立（plan 07 §9-23）。
   修掉数据缺陷后，同一配置下真实臂 **1672.99** vs 打乱臂 **3875.21**（打乱 **2.32×** 更差）⇒ **PASS**。

## 提议

**τ 轴终点 = `min(谱面口径, 音频时长)`**，即 `T = tau_bins_for(min(chart.duration_s(), audio_duration_s))`。

1. **音频时长是事实源**：取**特征缓存元数据**的 `FeatureCacheMeta.duration_s`
   （几 KB 的 JSON，索引期每行只读一次；它本身有 `frames ≈ duration × rate` 的校验）。
   **不给清单加字段、不重跑 `pairs`、不读特征数组**。
2. **保留谱面口径作为上界**：当 `chart.duration_s() < 音频时长` 时**不补长**（谱面没写到的尾部不生成空窗×2）；
   即 `min` 而非「一律用音频」。
3. **显式记账**（`DatasetIndexStats`，落训练日志）：`tau_end_truncated_rows`（被截断的行数）、
   `tau_end_truncated_seconds`（省下的空窗时长）、`events_beyond_tau_end`（**被口径丢弃的事件数**，
   RPE 允许 note 落在音频之外，本口径会丢它们——因此必须可见）、`tau_end_fallback_rows`（元数据缺失时回退）。
4. **可回退、可对照**：`data.tau_end_policy = "audio"`（默认）/ `"chart"`（旧行为）；
   `data.tau_end_s` 仍可**显式**覆盖一切。回退只需一行配置。
5. **不改契约侧的 `PhigrosChart.duration_s()`**：它继续作为「谱面自身的保守上界」存在
   （其它调用方——QC 的 `time_span_s`、审计——需要它）。τ 轴终点是**数据集/训练口径**，不是 IR 语义，
   因此把决定放在 plan 02 的 dataset 层，而不是改 `core/contracts`。

### 本 RFC **不**决定的两件事

- **是否含 `META.offset`**：offset 的符号与作用点仍是存疑项（plan 00 §9-6 / plan 02 §9-9 / 存疑 D10），
  本轮不动它；
- **`chartTime` 的原始语义**（谁写坏的、是否某个编辑器的单位换算）：不影响本决定，
  因为无论其语义如何，它都已被证明**不可作为时间轴长度的事实源**。

## 备选方案

| 方案 | 放弃理由 |
|---|---|
| **最后一事件**（忽略 `chartTime` 与音频） | 会丢掉「音频还在放、谱面已写完」的尾奏（真实谱面常见），且把轴长绑在**单个 note** 上——一张谱只要有一个远端 note，整条轴仍会爆掉（chart 27751 的 note 最远只到 121 s，看似安全，但那是巧合而非保证） |
| **音频时长 + 固定余量** | 余量没有事实来源；且真实数据里 note 超出音频的只有 228 张（2.7%），加余量等于让 97% 的谱面多切空窗 |
| **清洗数据**（重写/剔除 `chartTime` 异常的谱面） | 剔除会丢掉 53% 的语料与其中全部**早期合法窗口**（chart 27751 的前 103 个窗是真实内容）；重写是**不可追溯地改原始数据**，违反合规留痕纪律 |
| **按分位数截断**（如 `p99`） | 没有物理意义，且阈值成了新的魔数 |
| **保持现状但把异常谱面隔离** | 等于放弃 53% 语料；且「异常」判据仍需要一个锚（音频时长），绕回本提案 |

## 后果

- **采纳后**：train split 从 3361 万窗降到 **634 952 窗**；全库索引 2.3 h → 36.5 min（且有落盘缓存）；
  真实 200 行切片门禁 **G1-G4 首次全绿**（plan 07 §9-25）；真实数据训练的前置**只剩算力**。
- **代价与风险**：
  1. τ 轴终点**依赖特征缓存**：换特征缓存会让索引指纹变化 → 自动重建（不会静默用旧轴）；
  2. `audio_duration_s` 本身来自音频解码，对 79 首解不开的音频（plan 02 第三轮）不存在——
     这些行本来也进不了清单（缺特征），因此不受影响；
  3. 本口径**丢弃**落在音频之外的 4554 个事件（全库，占 1107 万的 0.04%），已显式记账；
     若评审认为这些事件必须保留，正确做法是**先裁定 offset/音频对齐口径**，而不是恢复 `chartTime`。
- **对既有文档的修订**：plan 03 §9-14 从「未查证」改为「已实测 + 本提案」；plan 02 §9 第四轮补充实测；
  plan 07 §9-23 的「G2 结构性失效」**结论作废**（其三条候选控制设计 a/b/c 不再需要实现）。

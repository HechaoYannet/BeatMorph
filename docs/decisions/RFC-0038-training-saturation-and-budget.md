# RFC-0038 — 全量大训练首跑「零进展」的处置：预算收敛、val 量具修复与诊断前置

- 状态：**提案**（待决策者裁定） ｜ 提出日期：2026-09-29 ｜ 决定日期：（待定）
- 提出者：主会话（infra-agent，plan 07）
- 影响模块：**07**（训练循环 / 配置 / 文档）、**06**（val 指标口径）、04（仅诊断，不改目标）

> 触发来源：**首个跑到 `max_steps` 并正常退出的全量 run**（`runs/phigros_masked/20260928-144342`，
> 20000 步，exit 0）的实测——完整记录见 plan 07 **§9-61**。本 RFC 只处理**它暴露的三个问题**：
> ① 20k 步零学习进展（§9-61 ①）；② val 既**贵**又**检验力不足**（§9-61 ④1/④2）；
> ③ 音频条件的边际价值 ≈ 0（§9-61 ③）。**本 RFC 不改损失函数、不改门禁、不改红线本身。**

## 1. 背景（三条实测事实）

**F1 — 这一版目标/优化器在 step ~1000 饱和。** 非空窗 per-event 训练损失按 2000 步分块的中位
**9.52 → 10.24**（10 块无趋势）、均值 **10.54 → 11.66**；`val/ratio` 的最优值停在 **step 2000
（0.7292）**，之后 18000 步一个点都没超过它。即 **20000 步里约 19000 步买到 0**。

**F2 — 判读红线单点破（规则已自动执行，不需新裁定）。** 20 个 val 点里 `val/ratio >= 1` **1 个**
（step 3000 = 1.0033）⇒ 按 RFC-0037 R1 **该 run 的扩规模结论作废**；
`val/nll_shuffled_delta` **20/20 > 0**（均值 +0.688）⇒「输入对目标有信息」未被推翻。
⚠️ 但要如实记下**量具限度**：`val/ratio` 的**残差 sd = 0.067**，而全程漂移只有 +0.13（t = 1.73，不显著）
⇒ **漂移与量具噪声同量级**，「破 1」这个判据目前是**低检验力**的（§9-61 ④1）。

**F3 — 音频条件在遮盖测度下几乎不被使用。** 同批同权重的 no_grad 前向差分（20 个 val 点）：

| 干预 | Δ 范围 | 占 `val_nll`（≈1.06） |
|---|---|---|
| 音频**帧轴置换**（分布内，只破坏对齐） | −0.0030 … +0.0059 | **≤ 0.6%** |
| 音频置零 | −0.0619 … +0.0590 | ≤ 6% |
| 事件轨置零 | +0.0486 … +0.3186 | 4.6% … 30% |

（方法学前提已核查：置零的 Δ 不是 0 ⇒ 缓存音频不是退化常量。**这不等于「音频没用」**——
可见场本身携带大量信息，且该读数只说明**当前目标没有奖励模型用音频**。见 §9-61 ③。）

**F4 — val 是墙钟第二大项，且它自己撑不起判据。** Σ val 墙钟 **2234.9 s = 97.3 min 的 38.3%**
（训练步总和 3252.9 s，val/step = 0.687）；单次 73.0–190.3 s 摆动（§9-59：跨墙）。
同时它只有 **128 窗 / 5081 线 / 498 事件**，**57.8% 的窗口是空窗且对 `val_nll` 恰好贡献 0.0000**，
实际由 ~42% 的窗口承载。**20 个 val 点里没有任何一个改变了处置**（首点即最优区间，红线破点后恢复）。

## 2. 提议（R1–R5；R1–R3 是配置/口径，R4 只测量，R5 是流程规则）

### R1 预算收敛（纯配置，**不参与续训指纹**）
`optim.max_steps: 20000 → 4000`、`optim.val_every: 1000 → 500`（8 个 val 点）。
理由：平台在 step ~1000–2000（F1）；后 90% 的步无信息。两个字段都已在
`checkpoint.RESUME_IGNORED_KEYS` 中（`optim.max_steps` / `optim.val_every`）⇒ **不改指纹、不需另起目录**。
**预计**：一次全量跑从 97.3 min 降到 **≈22 min**（4000×0.163 + 8×55 + 门禁 3.5 min），
**同一墙钟内可跑 4 个配置**——这正是分离 F1 根因所需要的通量。

### R2 对照臂降频（新增 `optim.val_contrast_every`，默认 1 = 现状）
`evaluate_val` 已有 `contrast: bool` 形参；把它接到「每 `val_contrast_every` 次 val 才跑 3 个
条件臂」。**红线指标（`val/nll` / `val/nll_shuffled_delta` / `val/ratio`）每次都跑，语义一字不改**，
只有 `cond_*_delta` 变成低频。理由：val 有 **5 个前向臂**（模型 + 置换 + 3 条件），
实测 **0.157 s/窗/臂**（对照 schema 里的 0.09 s 模型，偏 1.7×；叠加跨墙后 0.26 s）
⇒ 砍掉 3 臂可**省 60% 的 val 前向**。该字段须一并加进 `RESUME_IGNORED_KEYS`（同 `val_windows` 理由）。

### R3 val 检验力（**二选一或两者，须裁定**）
- **R3a 加大集合**：`optim.val_windows: 128 → 512`。成本 ×4（单次 val 约 200–500 s，且跨墙更久）
  ⇒ **与 R1/R2 组合后仍可接受**（8 点 × ~220 s ≈ 29 min，与训练相当）。**不改指标定义**。
- **R3b 改判据形态**：把 RFC-0037 R1 的**单点**红线（「任一 val 点 ratio ≥ 1 即作废」）改为
  **趋势判据**（如 3 点移动均值 ≥ 1，或连续 k 点不改善），并同时给出 shuffled_delta 的
  **margin**（RFC-0037 §6-2 的未决项）。⚠️ **这触及 RFC-0037 R1 的判读红线文字 ⇒ 属修宪，须明示裁定。**

### R4 诊断前置（**不改生产代码、不改损失语义**；3 个有界探针，各 ≤10 min，产物落 `runs/_probe_*`）
1. **可学性上界**：固定 16 个真实窗（有事件），跑 2000 步看**总体**训练损失能降到多少
   （对照：G1 已在 1 个批上 300 步降到 2.56 ⇒ 模型**能**拟合单批）。判据：若能降到
   ≪ 平台值（10.2/事件）⇒ 平台是**优化器/目标**问题；若不能 ⇒ 更像**不可约熵**。
2. **有效步长扫描（3 臂）**：`lr` = 3e-4（现状）/ 1e-4 / 3e-5，各 1500 步，同种子同数据顺序，
   比 per-event 损失轨迹。判据：**更小的 lr 在同样步数下更低 ⇒ 有效步长是瓶颈**
   （现状 `clip_active` = 非空步 **100%**（RFC-0037 §6-1 / §9-61 ⑤），有效更新 ≈ `lr·g/‖g‖`）。
3. **音频通路探针**：一次反传，统计 audio 分支（含 LoRA 适配器）的梯度范数占比，回答
   「音频没被用」是**梯度不存在**还是**梯度存在但目标不需要**（F3 的两种解释）。

### R5 停机规则显式化（写进 `docs/TRAINING.md`）
**连续 4 个 val 点 `val/ratio` 不优于已有最优 ⇒ 停止该 run**，在 plan 07 记录后另议；
`best.pt` 始终按 `val/ratio` 保留。理由：20k 步实测里，红线判据只给出一个单点信号，
而「长期不改善」才是可执行的停机条件（F1/F4）。

## 3. 备选方案（及放弃理由）

| 方案 | 判断 |
|---|---|
| **A1 直接改优化器**（cosine 衰减 / 把 `grad_clip_norm` 提到 ~32 并相应降 lr） | **先不做**。`lr·g/‖g‖` 与 Adam 同族（每坐标有效步长 ≈ lr），「Adam 恒定 lr 走不动」不是既有事实；先由 **R4-2** 拿证据再开新 RFC。 |
| **A2 直接改目标**（提高遮盖率 / 加大 `t_window` / 去掉可见场） | **本轮不做**。改变训练语义与数据分布，须有 R4-1/R4-3 的证据后另开 RFC。 |
| **A3 保持 max_steps=20000 继续跑** | **否决**：实测后 90% 无收益，且 val 吃掉 38% 墙钟。 |
| **A4 只压 `val_every`** | **不充分**：单次成本不变，且 F4 的检验力问题依然存在。 |

## 4. 后果

- 采纳 **R1 + R2 +（R3a）** 后：单次长跑 **97.3 min → ~22–29 min**，val 占比从 38.3% 降到
  ~30%（臂数减 60% 抵掉窗口数增 4×），**判据的检验力提高 4×**（事件数 498 → ~2000）。
- **不触及** CLAUDE 红线 1/3/7：损失函数、门禁 G1/G3/G4、判读红线的**文字**（除非选 R3b）都不动；
  训练语义不变 ⇒ 与既有 run 的**跨 run 可比性**保持不变（仍与 RFC-0037 之前的 run 不可比）。
- 需要的新增项：`optim.val_contrast_every`（schema + 校验 + 单测 + `RESUME_IGNORED_KEYS`）、
  plan 07 §4.3 的 val 预算表、`docs/TRAINING.md` §7.5 的停机规则。
- ⚠️ **schema 里 val 预算的推导值（0.09 s/窗/臂 ⇒ 单次 37 s）与实际（0.157–0.26 s ⇒ 100–190 s）
  相差 3–5×**，随 R2 一并更正（§9-59/§9-61 已记录）。

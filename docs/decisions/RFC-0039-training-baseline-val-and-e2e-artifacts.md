## 1. 背景（为什么现在裁）

§9-61 把首次全量 20 000 步判为「零进展」，但当时**分不清「学完了」与「学不动」**。§9-62 用十余个一次性探针把它拆开，
结论是**「学不动」，且原因是一处结构性缺陷**：

1. **根因 = 输出头的直连 skip**（`cell_skip` / `cum_skip`，plan 04 §9-17 为**合成**任务引入）。
   对**被遮盖 token**，它的输入恒为常数 `[0…0, 1…1]` ⇒
   - 只能给出**与 token 无关的空间先验**：实测与真实事件格**反相关**（命中率 **0.367 < 0.5**），
     token 内空间分布熵仅 **1.88 / 7.16** nats（近似 one-hot）；
   - 这条「容易的路」让 **trunk 学不动**：权位移实测 trunk **5–20%**、head **1100–2900%**（`cell_skip` 单层 **33×**）；
   - 于是**一切条件通路形同虚设**——一条机制解释了此前全部零结果（音频 0.6%、对齐修复无效、直连注入无效、
     `lr=1e-3` 崩、熵正则付了惩罚但熵不变）。
2. **解法 = `model.head_skip=false` + `model.audio_align=true`（串联才生效）**，三条独立证据线一致：

   | checkpoint（512 窗 / 139 批配对） | `val_nll` | `val_ratio` | 配对 t |
   |---|---|---|---|
   | baseline@20000（skip=on） | 1.6201 | 0.9608 | — |
   | `head_skip=false` | 1.5959 | 0.9465 | +1.16 |
   | `head_skip=false` + `audio_align=true` @24000 | 1.3827 | 0.8201 | +2.44 |
   | **同上 @40000（arm H）** | **1.2568** | **0.7454** | **+3.03** |

   - **训练侧**：非空窗 per-event 中位 **10.04 → 8.85**，末步 **0.015**（平台消失）；
   - **机制侧**：空间命中率 **0.367 → 0.750**、音频置零代价 **0.012 → 4.97**、事件轨置零代价 **0.049 → 0.495**、
     x 边缘相关 **0.583 → 0.801**；
   - 收益在 **step 8000 就已达标** ⇒ 是「**能学**」而不是「学得久」；
   - 同一 `audio_align` 在 **skip=on** 下**完全无效**（臂 C）⇒ 两道闸**串联**（这本身是已验证的机制陈述）。
3. **量具已被证明有系统偏差**：**128 窗 val 系统性偏乐观**（基线 0.887 vs 512 窗 0.961）；
   且**训练流沿计划位置非平稳**（事件/窗中位 **2.5 → 12.0**、空窗 **48% → 5.5%**，按桶轮转发牌、小桶先抽空）。

## 2. 裁定（三条，均已通过）

### R1　两个开关**转正为基线配置**

- `model.head_skip`：`true` → **生产配置取 `false`**（移除输出头对**原始输入特征**的直连 skip）。
- `model.audio_align`：`false` → **生产配置取 `true`**（把**与该 τ 切片同一时刻**的音频帧及其差分投影后直连注入 token）。
- 落点：`configs/phigros_masked.yaml` **显式写出**这两项（配置文件是训练语义的权威记录）；
  **schema 的代码默认值保持原行为**（`head_skip: bool = True` / `audio_align: bool = False`），
  以免 `smoke` 等其它配置与门禁在无提示的情况下改变行为。**转正的依据是配置，不是默认值。**
- 二者**必须成对**：只开 `head_skip=false` 只拿到一小部分收益（0.9465），只开 `audio_align=true` 完全无效（0.9608）。
- **修订 plan 04 §9-17**：该节「没有直连 skip 就会停在只学边际分布的盆地」的结论**在真实任务上不成立**——
  `head_skip=false` 下门禁 **G1 仍 PASS**（4646.7 → 2.46），且真实训练损失与 val 均显著改善。
  该结论的适用范围回退为「**合成的最小复述任务**」。

### R2　val 集合**重选 + 扩大**

- **现状缺陷**（§9-62 ⑪⑫㉒㉕）：128 窗由 `_slots()` 从**每桶前 `val_batch` 个**取出 ⇒
  只覆盖 32 个桶、57.8% 空窗、事件/窗中位 **0**，比训练流与 512 窗总体**系统性容易**；
  主判据的自噪声 sd ≈ 0.067，而本轮所有效应都在 0.04–0.15 量级。
- **裁定**：val 窗口数 **128 → ≥512**（首版 512），并把抽取口径从「按桶前 N 个」改为**跨桶、按事件密度分层**的
  确定性抽样（同一 `seed` 逐位可复现），**构成必须落盘并打进日志**：空窗占比、事件数、`lines`、`K` 分位、窗口集合指纹。
- **代价与后果（如实登记）**：
  - val 单次墙钟按窗口数线性上升（512 窗 ≈ 4×，实测单点 8–10 min）；`val_every` 需按预算重设；
  - **历史 val 数字与新集合不可比**（同一 `val_windows` 不同 ⇒ 不同总体）⇒ 旧 `val/ratio` 只能作**历史记录**，
    不得与之后的 run 直接比较；
  - `optim.val_windows` **不进续训指纹**（`checkpoint.RESUME_IGNORED_KEYS`），故改它不需要重训。

### R3　新增机制：**每 20 000 步端到端生成一张谱面，供人工审阅**

- **目的**：NLL / `val_ratio` 都回答不了「模型到底会不会写谱」。需要一条**端到端产物**通道，
  让决策者直接看**生成的谱面文件**（而不是看曲线）。
- **触发**：每 **20 000 步**（`run.e2e_every`，默认 20000；与 `save_every` / `val_every` 解耦，均**不进续训指纹**）。
- **输入（已就位，决策者 2026-09-29 提供）**：`tests/e2e-val/`，由 `meta.json` 声明路径——
  `audio/fudahuang.mp3`（8.6 MB）与 `feature/fudahuang.npz`（30 MB；MERT **第 12 层**、
  **75.0 Hz**、dim 1024、float16、时长 **214.31 s**，见同目录 `feature/fudahaung.json` 的
  `rate/sample_rate/layer/feat_dim/dtype` 元数据；**文件名拼写以磁盘为准**）。
  - ⚠️ **固定不换曲**：同一首歌在每个 20k 步产物上重放，跨 step 才可比。
  - ⚠️ **`audio/` / `feature/` / `outputs/` 一律不入库**（数据合规硬约束②）：`.gitignore` 按目录忽略；
    只有 `meta.json` 这类**指针清单**可入库。
  - ⚠️ 生成范式是「**条件**生成」⇒ 还需要**判定线事件轨**。首版须明确轨的来源（取该曲在训练语料里的轨，
    或先跑无条件生成），并把它写进产物元数据——**实现时定，本轮不定**。
  - ⚠️ `meta.json` 的 `"json"` 字段当前指向 `feature/fudahuang.npz`（疑为笔误，应指特征元数据 json）；
    实现时以 `audio` / `feature` 两字段为准并**就地更正**。
- **产物落点与命名**：`tests/e2e-val/outputs/<YYYYMMDD-HHMMSS>-step<N>/`，目录内至少含
  ① 生成的谱面 `chart.json`（**RPEJSON**，主路径唯一权威格式）、
  ② `meta.json`（step / 配置指纹 / 音频与轨的来源与哈希 / 随机种子 / 生成耗时）、
  ③ `notes.txt`（可选：人类可读的一行摘要，便于快速扫）。
  **命名按时间即可**（不覆盖历史产物）。`tests/e2e-val/outputs/` **本地落盘、不入库**（数据合规硬约束②的同一条纪律：
  生成物来自训练语料，只作本地审阅）。
- **不是门禁**：本机制**不产生 PASS/FAIL**、不阻塞训练、不参与模型选择。它是**给人看的证据**，不是判据。
  失败时只告警并继续训练（与 val 的失败降级同口径）。
- **解码路径**：必须走 `decoder/` 的**合法性与可玩性后处理**（红线 6：导出前必须空违规项），
  因此本机制同时是 plan 05 解码链的第一条真实端到端用例。

## 3. 备选方案（及放弃理由）

| 方案 | 放弃理由 |
|---|---|
| 只把 `head_skip=false` 转正 | 只拿到一小部分收益（0.9465 vs 0.8201）；音频通路仍然接不上 |
| 把两个开关写进 `ModelConfig` 的**代码默认值** | 会静默改变 `smoke` 等其它配置与门禁的行为；转正应落在**生产配置**这一处 |
| 保留 128 窗 val，只把**红线判据**改成趋势判据 | 治标：128 窗的问题不只是噪声，而是**总体选错**（57.8% 空窗、事件/窗中位 0）；扩大 + 重选才治本 |
| e2e 生成物入库 | 与数据合规硬约束②冲突（谱面数据不得入库），且会随 run 数无界增长 |
| e2e 生成做成自动门禁（如「必须可玩」） | 现阶段判据无法定标（没有基线谱面、没有可玩性度量），做成门禁会变成**恒真或恒假**的假证据 |

## 4. 后果

- `configs/phigros_masked.yaml` 新增 `model.head_skip: false` 与 `model.audio_align: true`（**已在本次落地**）；
  `model.seconds_position` 与 `optim.cell_entropy_weight` 保持 `false` / `0`（**已实测无效**，见 §9-62 ⑦ 臂 A / ⑮ 臂 D）。
- plan 04 §9-17 的结论**就地更正**（适用域回退到合成任务）。
- plan 07 §9-62 增补 R1/R2/R3 的验收判据；`docs/TRAINING.md` 需在实现 R2/R3 时同步（**本轮未做**）。
- **待实现（下一轮，本轮不做）**：R2 的抽取口径与构成落盘、R3 的触发钩子 / 产物写出 / `tests/e2e-val` 骨架。
- **不可逆的记账**：R2 生效后，`val/ratio` 的数值整体换总体，**历史曲线不再可比**。

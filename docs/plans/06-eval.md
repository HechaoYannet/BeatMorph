# Plan 06 — 评估与实验设计（指标 / 协议 / B1-B6 对照臂 / 人评）

## 1. 目标与范围

### 1.1 交付什么

把 RFC-0029 §5 的评估设计落成**可跑、可复现、可审计**的代码与协议：

1. **事件级指标库**：F1 **双容差**（±20 ms 对齐 DDC 口径、±50 ms 对齐 GenéLive! 口径）、**单独报告全谱相位偏移**、**背面 recall**、`positionX` MAE、类型准确率与侧别准确率；并按**时间组**（含 12/24 三连）与**难度**分解。
2. **匹配与报告协议**：贪心一对一匹配；**未匹配的生成事件留在分母**；**按谱平均与 micro 平均都报**；**「固定解码规则」与「每谱最优」两栏**（ITGPT 实测同一模型 F1@0.5 = 0.7801 vs Max F1 = 0.8022，DDC 更极端 0.5006 → 0.7317）。
3. **校准指标**（NLL）与**探索性指标**（能量相关性）的隔离与标注。
4. **指标准入机制**：corruption 测试（dose-controlled 注入已知失败 + 不变性控制）。
5. **B1-B6 对照臂实验矩阵与验收表**（RFC-0029 §5.2「全部必须实现，缺一不可」）。
6. **人评协议**：MIREX 2026 三段式的 Phigros 版执行手册。

### 1.2 不交付什么

- 不实现任何生成模型（Plan 03/04）；不实现解码器（Plan 05）；
- 不定义训练目标（但**要求**任何新目标先过 G1-G4，见 §6）；
- 不做「星数计算器」类工具的实现——Phigros 是否存在公开等效难度计算器**未查证**（文献库 §7.5、§9-11）；
- 不做主观质量的自动化替代品：**NLL 不是质量分数**（§4.6）。

## 3. 接口契约

### 3.1 输入

```
EvalInput:
  pred   : PhigrosChart      # 生成谱（必须经 Plan 05 的后处理与合法性校验）
  gold   : PhigrosChart      # 人类谱
  config : EvalConfig

EvalConfig:
  tolerances_s   : list[float]   # 默认 [0.020, 0.050]（DDC / GenéLive! 口径）
  match_marking  : bool          # 时间匹配是否要求标记一致（见 §4.2）
  phase_search   : {off, on}     # 是否做 per-song 全局 offset 搜索
  phase_range_s  : tuple[float, float]
  phase_step_s   : float
  average        : {per_chart, micro, both}
  decode_regime  : {fixed, per_chart_best}
```

- **一切时间量以秒为单位**，字段名以 `_s` 结尾；**公共接口不得出现帧索引，也不得出现 τ 格索引**——场网格是 τ（beat-aligned，1/48 拍，Q15），评估在本模块**一律在秒域**进行，任何与拍/秒有关的换算经 `field/` 的权威接口（RFC-0029 §7-5/§7-8、POSTMORTEM §7-5）。
- `pred` 必须是**已通过合法性校验**的谱（否则评估的是「非法谱的质量」，结论不可用）；非法率由 Plan 05 的 `LegalityReport` 单独报告。
- 契约类型以 `beatmorph/core/contracts` 为准（红线 2）。现有 `beatmorph/core/eval.py` 的 `measure_reconstruction_accuracy` 是 v2.x 的 **lane 精确匹配**实现，不适用于 Phigros 标记空间，本 plan 的实现与之并存、不复用其匹配语义。

### 3.2 输出

```
EvalReport:            # 冻结字段，供 Plan 07 的日志与 Plan 08 的 CLI 消费
  per_chart   : list[ChartMetrics]
  aggregate   : {per_chart_mean: Metrics, micro: Metrics}
  breakdown   : {by_time_group: {...}, by_difficulty: {...}}
  calibration : {nll, nll_constant_baseline, nll_zero_is_inf: true}
  legality    : {violation_rate, out_of_range_ratio, cross_line_conflicts}
  exploratory : {energy_correlation}   # 标注 exploratory，禁止作主判据
  meta        : {seed, decode_arm, tolerance_s, phase_search, git_rev, data_rev}
```

- `meta` 是**强制**字段：任何报告必须可追溯到解码臂、seed、容差与数据版本（否则 B6 的结论无法解释）。

## 4. 内部设计

### 4.1 事件级指标定义

| 指标 | 定义要点 | 出处 |
| --- | --- | --- |
| timing-F1@±20 ms | 只比时间；TP = `abs(Δt) ≤ 0.020` 且一对一匹配 | DDC 口径（文献库 §7.1） |
| timing-F1@±50 ms | 同上，容差 0.050 | GenéLive! 口径（文献库 §7.1） |
| event-F1 | TP 还要求 `line_id` / `positionX` / `side` / `type` 一致 | GOCT 的 action token micro-F1（文献库 §7.2-7） |
| 背面 recall | 仅统计 `side == BACK` 的 gold 事件（实测背面只占 2.4–3.0%） | RFC-0029 §5.1、BasePlan §3.2.2 |
| 侧别准确率 | 在匹配对上统计；**必须与「全预测正面」基线并列报告**（该基线约 97.5%，因此总准确率无判别力） | 数据集实测（survey §7.3） |
| 类型准确率 | 在匹配对上统计 Tap/Drag/Hold/Flick；同时报每类 recall | 文献库 §7.2-7 |
| `positionX` MAE | **只在匹配对上**计算；另报「由 `dx` 决定的量化下界」作为参照 | 本 plan（量化下界见 §4.5） |

### 4.2 匹配协议

1. **贪心一对一**：pred 与 gold 各按时间排序，按时间差升序贪心配对，每个 gold 至多匹配一个 pred（STRUM 做法，文献库 §7.2-1）。
2. **未匹配的生成事件留在分母**：precision 的分母 = 匹配数 + 未匹配 pred 数（ChartGenEval 的 timing clean rate 明确 *Unmatched generated notes remain in the denominator*）。否则「少生成」可刷高 precision。
3. **两族指标必须分开报**：`timing-*`（只比时间）与 `event-*`（标记全等）。理由：文献里时间 token 与 action token 是两条独立的报告轴；混在一起无法定位误差来源。
4. **匹配不跨线贪心**：一条 pred 与其最近 gold 的时间差可能极小而线号不同——必须由 `event-*` 这一族暴露，**不得**在 `timing-*` 里偷偷要求线一致。

### 4.3 全谱相位偏移（必须单独报）

背景：STRUM 实测人类谱面事件**只有 89.0%** 落在音频 onset ±100 ms 内（n = 39,136 鼓事件），因此 recall 存在一个**与音频无关的上界**；谱面生成不是转录而是**创造性诠释**（BasePlan §1.3）。

- 实现 **per-song 全局 offset 搜索**：对每首曲在 `phase_range_s` 内以 `phase_step_s` 搜索使 timing-F1 最大的整体偏移；
- **必须报告「搜索」与「不搜索」两组数**（RFC-0029 §5.1、文献库 §8.4-9）；
- 同时报 **grid-phase offset**（全谱最佳对齐偏移本身）作为独立读数（ChartGenEval 三档网格加权 0.2/0.3/0.5 的做法**可选采纳**，具体权重是否照搬见 §9）；
- 若「搜索后」显著优于「不搜索」，则说明时间对齐本身是主要误差源——**这个结论必须写进报告结论段**，而不是只放一张表。

### 4.4 分解报告

1. **时间组**：1/4、1/8、1/12（三连）、1/16、1/24（三连）、1/32（GOCT 的分解法，文献库 §7.2-5；三连组不可省）。归组规则（最近 beat 细分）必须显式声明且**与解码网格无关**（否则分解会自我实现）；归组所需的「秒 → 拍细分」换算**经 `field/` 的权威实现**，不在本模块内重写 BPM 分段积分（红线 7）。注意：场本身就在 τ 网格上（1/48 拍），因此「与网格无关」这条要求在本 plan 中必须由测试显式保证。
2. **难度**：`difficulty` 是 **f32**，且**必须 round 到 0.1 再比较**（数据集实测存在 `14.900001` / `18.000004` 这类浮点误差）；`level` 是自由文本（实测出现过 `"AT  Lv.16"`、`"sweet"`、`"酔い"`），**绝不可 regex 解析**（survey §3.2）。
3. 低难度必须单独成档：文献一致报告低难度是难点（DDC 在高难度已达人类竞争水平但低难度有改进空间；GOCT 报告低难度灾难性失败），**不得把低难度当作「顺带能做」**。

### 4.5 `positionX` MAE 与量化下界

- 只在匹配对上计算 MAE（未匹配事件的 `positionX` 无对应真值）；
- **必须并列报出量化下界**：若解码输出被吸附到桶中心、真值在桶内近似均匀，则期望绝对误差 = `dx / 4`（`dx = RPE_STAGE_WIDTH / x_bins`）。【推导，本 plan 自证】
- 该下界随 `x_bins` 变化 → `x_bins` 的消融（`N ∈ {64,128,256,512}`，单位文档 §7.3 要求）必须与 MAE 一起报，否则 MAE 的改善可能只是网格变细。

### 4.6 校准指标：NLL（**只作校准，不得作质量分数**）

- 报验证集泊松 NLL，并**同时**报 **G3 常数基线** `λ0 = N/abs(Ω)` 的 NLL（RFC-0029 §3.2：常数基线**不是** `λ ≡ 0`，后者 NLL = +∞，应写成契约断言）；
- ⚠️ **硬约束**：ChartGenEval 实测 perplexity 在「常见图案重写」腐败下**下降 37%**（9.44 → 5.98）、self-similarity 在「循环塌缩」下**上升 62%**——**两个指标都会朝错误方向移动**。因此 **NLL 不得作为模型选择的主判据**，只能用于概率校准与门禁（G3）。
- 报告模板的头部必须固定一行警示：`NLL 是校准读数，不是质量分数`。

### 4.7 探索性指标：音乐能量相关性

- 「密度曲线与音乐能量曲线相关性」在 ChartGenEval 中被明确标注为 **Exploratory development analysis**（无 held-out 证据）；
- 因此：**可以报，但必须标注 exploratory，且不得作为模型选择主判据**（RFC-0029 §5.1、BasePlan §9）；
- 与 onset 支持率（STRUM 的 89.0% 上界）一起报时，必须注明「未匹配到人类谱」与「未匹配到音频」是两件事。

### 4.8 指标准入：corruption 测试

对**每一个**候选指标：注入 dose-controlled corruption，要求三条同时成立（文献库 §7.6(c)）：

1. 目标读数随失败强度呈**负的 dose-rank 关联**；
2. 最强剂量与匹配对照**显著不同**；
3. 所有**预先声明的不变性控制**通过。

标配注入集（本 plan 拟定，可直接实现）：① 全谱时间偏移（0 → 容差的数倍）；② 类型打乱；③ 侧别翻转；④ 循环塌缩（重复片段）；⑤ 密度缩放（保持结构、只改数量）；⑥ 局部爆发（单点密集堆叠）。

统计：song-cluster bootstrap 区间 + 多重比较校正（具体方法见 §9）。**未通过 corruption 的指标只能进附录，不得进主报告。**

### 4.9 B1-B6 对照臂矩阵（RFC-0029 §5.2：缺一不可）

> ⚠️ **对照层级必须逐臂声明**：absorbing-state 离散扩散的 NELBO 在时间步加权下**等价于掩码位置上的加权交叉熵**（arXiv 2510.03289 式 (10)），因此「掩码补全 vs 离散扩散」比的是**训练目标/加权形式**；「find_peaks vs thinning」比的是**采样/解码策略**。两者不是同一层的差异，混谈则消融不可解释。

| 臂 | 内容 | 对照层级 | 必需固定量 | 不可省的理由 |
| --- | --- | --- | --- | --- |
| **B0** | `λ0 = N/abs(Ω)` 常数基线；随机事件基线 | **门禁基线（非消融臂）** | `abs(Ω)` 的定义（Plan 00 §3.7）与标度归一化口径（§9-6） | G3 判据；给出「什么都不学」的下界 |
| **B1** | 热图 + focal loss（CornerNet/CenterNet 配置）+ Hamming 平滑 + 每难度阈值 | 训练目标 | 目标 y 是**未归一化**高斯（积分 ≠ 事件数）→ **不得与泊松 NLL 混用损失** | 文献主流做法，**必须是正式消融臂而非稻草人** |
| **B2** | **主线**：泊松 NLL 强度场 + 掩码补全 | 训练目标 + 架构 | ∫λ 与场同网格（τ 轴，测度含 `J(τ)dτ`，Q15）；分辨率显式声明 | 本方案主选 |
| **B3** | 离散 event token + 自回归（GOCT 配置为骨架） | 表征 + 训练目标 | token 化方案（time token 细分 × line/side/type/x 桶） | 唯一能与文献数字对话的臂 |
| **B4** | **自回归上界臂** | 采样策略（顺序） | 与 B3 同 token 化 | arXiv 2510.03289 对并行采样的质疑要求 AR 上界 |
| **B5** | 掩码**离散**扩散（absorbing） | 训练目标（时间步加权形式） | 明确声明与 B2 比的是训练目标层 | 检验「连续场 vs 精确离散」的取舍 |
| **B6** | 解码策略消融：`find_peaks` vs **Ogata thinning** | **采样/解码策略（独立变量）** | 同一模型权重、同一 seed 集 | 解码是独立变量，不能与损失混谈 |

**验收表（每臂必填，缺格即验收不通过）**

| 验收项 | 判据 |
| --- | --- |
| G1-G4 门禁 | 该臂若含**新训练目标/损失**，必须先过 G1-G4 并把 `summarize()` 输出写入训练日志（§6 硬性） |
| 报告完整度 | timing-F1 双容差 × 按谱/micro × 固定/最优两栏 + 相位偏移两组数 + 背面 recall + `positionX` MAE（含量化下界）+ 类型准确率 + 分解（时间组 × 难度）+ 合法性率，**全格非空** |
| 规模声明 | 训练样本数、曲目数（唯一曲目数）、时长必须与结论一起给（GOCT 的小数据上输给 CNN、大数据上胜出说明**规模是判别力的前提**） |
| 对照层级声明 | 每臂一行说明「比的是训练目标还是采样策略」 |
| 可复现 | `meta` 含 seed / 解码臂 / git rev / data rev；固定 seed 重跑逐字段一致 |

### 4.11 人评协议（MIREX 2026 三段式，最终金标准）

1. **算法评估**：人工挑 3 首曲；先检查**难度条件是否生效**，再用 Plan 05 的 `validate()` 检测不可玩摆放（对应 MIREX 用 AiMod / MapsetVerifier 的位置）。通过者进入下一阶段。
   - ⚠️ MIREX 用 osu! star rating 计算器判难度条件；**Phigros 是否有公开等效计算器未查证**（文献库 §7.5/§9-11）→ 替代方案：ITGPT 的「诊断网络」思路（训练一个能从生成谱反推难度的辅助网络作为难度条件生效的证据）。
2. **专家评估**：约 **5 名**有经验的 Phigros 玩家/mapper 组成 jury，维度 = **音乐契合度 / 创造性 / 手感**，外加一个 **humanity score**（生成谱有多像人写的）。
3. **社区评估**：选一首 showcase 曲；玩家**按自身水平选择难度**，把各模型生成的谱与**人类谱混在一起试玩**，投票维度同上，并被要求**指出哪一张是人类写的**（盲测识别）。

**人评执行要求**：盲测必须双盲（呈现顺序随机、不标注来源）；量表用 Likert（文献库 §7.6(b)）；被试的音乐训练背景必须记录（个体差异影响审美判断）；人评**不得**引用 ChartGenEval 的 band 数值（其 band 只来自单一太鼓语料），只能引用其方法论。

## 8. 测试策略

**单元（默认 CI，无权重、无 GPU）**

- 匹配器：表驱动（同刻多音、时间并列、跨线近邻、空 pred / 空 gold）；
- 分母语义：断言未匹配 pred 计入 precision 分母（反向测试：删事件不应提高 precision）；
- 平均口径：`per_chart` 与 `micro` 在不等长谱上不同；
- 相位搜索：注入已知 δ 的解析用例；搜索边界与步长行为；
- 校准隔离：断言主判据不消费 NLL；`λ ≡ 0` → `inf`；
- 难度分档：`level` 文本不得参与分档（用 `"AT  Lv.16"` / `"sweet"` 等实测样本作负例）；`difficulty` 必须 round 到 0.1；
- **mock 纪律**：夹具不得固化物理常量（AGENTS.md §3.3）；容差必须来自 `EvalConfig` 而非测试内字面量。

**集成**：`chart + chart → EvalReport` 全链路（夹具级）；报告 JSON schema 冻结测试（字段缺失即失败）；

**corruption（可 CI 跑的小规模版 + `slow` 全量版）**：6 类注入的 smoke 版进 CI，全量带 bootstrap 的版本标 `slow`。

**e2e（`slow`）**：真实模型 → 生成 → 后处理 → 评估，产出完整报告（与 Plan 07 的日志落盘联合验收）。

## 9. 开放问题

1. **相位搜索的步长与范围未定**：ChartGenEval 用 **0.5 ms** 步长 + 三档网格加权 0.2/0.3/0.5；我们是否照搬其权重、搜索范围取多大，**未决**。步长直接决定搜索成本与「恢复多少 F1」。
2. **song-cluster bootstrap 的 cluster 定义**：同曲不同难度谱是否算同一 cluster？BasePlan §4.5 明确「同曲重复率**未统计**」→ 需先做全库统计。
3. **难度分档边界未定**：全库 `difficulty` 分布**未统计**（现有 9.9–18.5 / 中位 15.6 只是 n = 24 的近期偏置抽样，survey §3.4 有明确偏差声明）。
4. **时间组归组规则**：按「最近 beat 细分的类型」归类时，边界事件（正好在两个细分中点）如何归属；该规则与解码网格的耦合如何避免（否则分解自我实现）。
5. **多重比较校正方法未定**（Bonferroni / Benjamini-Hochberg / 置换检验），以及显著性水平。
6. **`abs(Ω)`（场体积）的定义已由 Plan 00 §3.7 裁定**：`abs(Ω) = k * t_bins * x_bins * sides * channels`（**含** K 与 type 通道）。→ 残留问题：`k` 随谱变化（实测中位 30、范围 2–82），因此 **NLL 与 G3 基线的绝对标度是 per-chart 的**；跨谱汇总与 G1/G3 阈值都需要归一化口径（如 NLL 除以事件数、或相对基线的改进比例），见 Plan 07 §9-2/§9-3。
7. **Phigros 无公开难度计算器**（未查证是否存在）→ 「难度条件是否生效」的代理指标需自建（候选：ITGPT 诊断网络）。
8. **背面样本量**：背面仅占 2.4–3.0%，测试集里能否给出有意义的置信区间，取决于测试集规模——需在划分方案定稿后核算。
9. **人评的音频播放/分发口径**：数据合规裁决（2026-08-05）解除了「训练可启动」的阻塞，但其文字与四条硬约束**未逐字覆盖「向约 5 名评审播放原曲音频」**这一再分发场景 → 仍待决策者明确（不得替决策者推定已被覆盖）。
10. **corruption 准入是否升格为宪法级门禁**（与 G1-G4 并列）：本 plan 按「评估流程内部约定」处理，如需写入 CLAUDE.md 须走 RFC。
11. **`beatmorph-eval` 的入口形态**（CLI 子命令 vs Python API）与 Plan 08 的边界，见 Plan 08 §9。

### 实施期裁定（主会话，2026-09-27）

M6.1–M6.6 落地时提出的 8 项口径问题，主会话按下列方式**接受为当前默认**（都已写进代码与测试，
其中 1-6 属「口径」，7-8 属「接口/覆盖范围」；仍需决策者复核的只有第 1 项的偏离登记）：

1. **新增第 ⑦ 类注入 `position_x_jitter`**（按 dose 沿 x 平移一个桶宽 `dx`）：接受。

2. **准入强度**：接受「声明响应集内 ≥1 个注入显著退化（bootstrap 区间上界 < 0 且 dose-rank rho < 0）

4. **相位搜索范围/步长**：接受临时值 **±100 ms / 1 ms**（§9-1 仍未裁定正式值），随 report meta 冻结。

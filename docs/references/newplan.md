# Phigros谱面生成技术参考文档

## 使用社区预训练音乐特征提取模型的完整技术方案


## 一、文档定位与核心假设

本文档面向Phigros自动谱面生成任务，假设采用以下技术路线：**使用社区已有的预训练音乐特征提取模型提取音频表示，通过Encoder-Decoder Transformer架构，将连续音乐特征转化为连续高斯概率分布形式的谱面表示，再经后处理离散化为Phigros可用的谱面事件。**

该路线继承了此前讨论的“连续到连续”核心思路，同时将音频特征提取环节完全外包给社区成熟模型，从而将主要精力集中于谱面生成任务本身。以下逐环节展开。


## 二、社区音乐特征提取模型选型

### 2.1 候选模型概览

当前社区可用的音乐自监督预训练特征提取模型主要有以下几个：

**MERT** 是目前音乐信息检索领域最广泛使用的通用特征提取器之一。它采用HuBERT架构，包含基于CNN的特征提取器编码24kHz原始波形，通过掩码语言建模风格进行自监督预训练，使用了RVQ（残差向量量化）和CQT（恒Q变换）两种教师模型提供伪标签。MERT-v1-95M在表征能力与计算成本之间取得了良好平衡，MERT-330M则提供更强的表征能力。MERT的Transformer层输出包含不同层级的信息——浅层偏向声学特征，深层偏向语义特征。

**MusicFM** 是ICASSP 2024提出的音乐信息学基础模型，同样基于Transformer架构，采用掩码token建模，使用BEST-RQ风格的随机投影量化器作为特征提取目标。MusicFM在MSD（百万歌曲数据集）和FMA-large上均有预训练版本，提供25Hz帧率的帧级表示。HuggingFace上提供了完整的模型权重和推理接口。

**MuQ** 是2025年提出的新模型，核心创新在于使用Mel残差向量量化（Mel-RVQ）代替随机投影或神经编解码器作为量化目标，解决了MusicFM随机投影量化器的不稳定性问题，同时避免了MERT对计算密集型神经编解码器的依赖。MuQ仅用0.9K小时开源数据即可超越此前模型，扩展到160K小时和迭代训练后进一步提升。Conformer编码器配合多层线性预测头是其核心架构。

**Myna** 是2025年提出的轻量级方案，采用ViT处理Mel频谱图，通过token masking（掩码90%的频谱图token）进行对比学习，支持4096的per-GPU batch size。Myna-85M在参数量仅为MERT-330M的1/4的情况下达到竞争力水平，且训练资源需求极低。

### 2.2 面向Phigros任务的选型建议

Phigros谱面生成任务对特征提取器的核心需求包括：**帧级时间分辨率**（谱面事件需要精确的时间对齐）、**音高与节奏感知能力**（谱面需要与音乐的音高轮廓和节拍结构匹配），以及**推理效率**（谱面生成可能需要处理完整歌曲的音频）。

**首选方案：MERT-v1-330M**。理由如下：MERT在音乐理解任务上的表征质量已被广泛验证，330M版本提供丰富的分层信息；其50Hz的帧率（5秒音频对应约250帧）对谱面事件的时间精度足够；社区生态成熟，HuggingFace和GitHub上有大量使用示例。具体使用时建议提取第3、6、9、12层的隐藏状态，这四层的拼接已被证明能同时保留声学细节和语义信息。

**备选方案：MuQ**。MuQ在多个下游任务上以更少的预训练数据超越了MERT和MusicFM，且Mel-RVQ的稳定性使其特征质量更有保障。对于需要频繁微调或对训练稳定性要求较高的场景，MuQ可能优于MERT。

**轻量级场景：Myna-22M或MusicFM**。如果Infra资源有限，Myna-22M-Hybrid以极低的训练成本达到了接近MERT-95M的性能；MusicFM提供25Hz的固定帧率输出，适配性强，且支持Flash Attention和混合精度推理。

### 2.3 特征提取的具体操作

以MERT-v1-330M为例，特征提取流程如下：

```python
from transformers import AutoModel
import torch

# 加载MERT-v1-330M
model = AutoModel.from_pretrained("m-a-p/MERT-v1-330M", trust_remote_code=True)
model.eval()

# 输入：24kHz单声道音频，长度不超过5秒
# 对完整歌曲，采用滑动窗口处理，window=5s，stride=2.5s
audio = torch.randn(1, 24000 * 5)  # 5秒音频

with torch.no_grad():
    outputs = model(audio, output_hidden_states=True)
    # 提取第3、6、9、12层
    hidden_states = outputs.hidden_states  # tuple of (num_layers+1) tensors
    selected = torch.cat([hidden_states[i] for i in [3, 6, 9, 12]], dim=-1)
    # selected shape: (batch, time_frames, 4 * hidden_dim)
```

提取后的特征通过时间平均池化或自适应平均池化调整到目标帧率。MERT的帧率约为50Hz（5秒音频约250帧），若谱面需要更高的时间分辨率，可保留原始帧率；若需要降低计算量，可使用自适应池化降至10-25Hz。

**冻结还是微调？** 对于Phigros任务，建议采用“冻结特征提取器 + 可训练Adapter”的方案。MERT的参数在训练中保持冻结，在特征输出后接一个轻量级的1D卷积ResNet或线性投影层，将其适配到谱面生成任务的表示空间。这一策略在MelodySim等任务中被证明有效：冻结MERT参数，仅训练后接的轻量级ResNet进行特征适配。如果数据量充足且需要更高精度，可解冻最后几层进行微调，但需注意过拟合风险。


## 三、谱面表示设计

### 3.1 连续高斯概率分布

将Phigros谱面表示为形状为 `(T, W, C)` 的连续张量，其中：
- **T** 为时间轴，对应特征提取器的帧率（建议25-50Hz）
- **W** 为谱面宽度，对应Phigros判定线的位置维度（建议归一化到[-1, 1]或[0, 1]）
- **C** 为通道数，对应音符类型（Tap, Hold, Flick, Drag）以及可能的Hold结束标记

对于每个音符事件，在 `(t_center, w_center)` 位置放置一个二维高斯核：

```
G(t, w) = exp(-((t - t_center)^2 / (2*sigma_t^2) + (w - w_center)^2 / (2*sigma_w^2)))
```

其中 `sigma_t` 和 `sigma_w` 是控制高斯宽度的超参数。`sigma_t` 建议设置为音符时间精度的1-2倍（例如在50Hz帧率下，sigma_t ≈ 2-3帧），`sigma_w` 建议设置为谱面宽度的2%-5%。

**关键设计决策**：不同音符类型使用独立的通道，而非单一通道内的不同数值。这是因为不同音符类型在语义上是正交的，共享通道会导致模型难以区分。Hold音符需要在起始帧和结束帧各放置一个高斯核，或使用额外的通道标记Hold的持续区间。

### 3.2 目标张量的构建

从Phigros谱面文件构建训练目标时，需注意：
- **时间对齐**：Phigros谱面使用BPM驱动的节拍时间，需将其映射到音频的绝对时间，再对齐到特征提取器的帧率。建议使用Phigros社区工具（如phichain或py-phi-editor）解析谱面文件。
- **去重与合并**：如果同一帧内存在多个音符，它们的高斯核自然叠加，形成多峰分布。模型学习的是叠加后的分布，解码时通过峰值检测还原为离散事件。
- **归一化**：确保每个通道的总能量或峰值幅度在训练集上归一化到统一范围，避免某些通道因音符密度不同而主导损失。


## 四、模型架构设计

### 4.1 Encoder-Decoder完形填空范式

如前所述，谱面生成更接近翻译而非自回归预测。具体架构如下：

**Encoder** 接收MERT提取的连续特征序列，通过若干Transformer层编码音乐上下文。Encoder的输入是 `(batch, T_audio, D_feat)`，输出是 `(batch, T_audio, D_model)`。建议使用滑动窗口自注意力代替全注意力——音乐转谱中的注意力权重具有强局部性，滑动窗口可以在保持性能的同时大幅降低计算量。

**Decoder** 以完形填空方式工作。在训练阶段，随机遮盖目标谱面张量中的部分时间片段（例如遮盖30%-50%的帧），Decoder接收被遮盖的谱面张量（遮盖位置置零）作为输入，结合Encoder的输出，预测被遮盖位置的完整高斯分布。这比自回归生成更适合本任务，因为谱面事件之间存在强烈的共现关系（同时出现的音符、连续的Hold序列等），完形填空允许模型同时利用前后文信息。

**Decoder输出层** 是一个线性层，将Decoder隐藏状态映射到 `(T_target, W, C)` 形状的张量，然后通过Sigmoid激活函数将其压缩到[0, 1]范围，对应高斯概率值。

### 4.2 长上下文与稀疏注意力

Phigros歌曲长度通常在1.5-3分钟，以50Hz帧率计算，输入序列长度可达4500-9000帧。全注意力在此时面临严重的计算和内存瓶颈。

建议采用**混合注意力方案**：
- **Encoder**：滑动窗口自注意力（窗口大小256-512帧）+ 每4层插入一个全局注意力层
- **Decoder**：滑动窗口自注意力 + 全局-局部交叉注意力，交叉注意力对不同音符类型使用不同的注意力范围（Hold音符需要更长的上下文以捕捉持续区间）
- **分层池化**：在Encoder和Decoder之间插入池化层，将时间维度压缩2-4倍，进一步降低计算量

研究表明，这种稀疏注意力方案在钢琴转谱任务上可将计算成本降低数倍，同时保持转录性能与全注意力基线可比。

### 4.3 难度条件与风格控制

Phigros谱面有多个难度等级。建议在Decoder的输入中注入难度嵌入——将难度等级编码为可学习的嵌入向量，通过交叉注意力或特征拼接的方式融入。ITGPT在DDR谱面生成中采用了类似策略，将难度和BPM作为条件特征整合到Transformer架构中。这使单一模型能够为不同难度生成适配的谱面。


## 五、训练策略与损失设计

### 5.1 损失函数

**主损失：二元交叉熵（BCE）** 。将目标高斯分布视为每个位置的“概率”，BCE在此场景下比MSE更稳定，因为BCE对预测值与目标值在接近0或1时的偏差更为敏感，有助于模型精确学习音符的起止边界。

**辅助损失1：起始点检测损失**。在时间轴上对每个通道的预测张量沿宽度维度求和，得到一个 `(T,)` 的一维序列，与目标音符起始点的二值序列计算BCE。这鼓励模型在音符起始时刻产生显著响应。

**辅助损失2：通道一致性损失**。对于Hold音符，起始帧和结束帧之间的所有帧应有持续的响应。可设计一个平滑损失，惩罚Hold通道在持续区间内的空洞。

**损失权重**：主损失权重为1.0，起始点损失权重建议0.3-0.5，通道一致性损失权重建议0.1-0.2。具体权重需通过验证集调优。

### 5.2 监督方式

考虑到Phigros官方谱面数据不公开，但社区有大量自制谱面（如Phira平台），建议采用**弱监督为主、自监督预训练为辅**的策略：

**阶段一：自监督预训练（可选）** 。如果谱面数据不足，可先用音频自监督任务（如掩码特征预测）预训练Decoder的初始参数。但考虑到MERT已经提供了高质量的音乐表示，这一阶段的收益可能有限。

**阶段二：弱监督微调**。使用社区自制谱面进行训练。社区谱面的质量参差不齐，可采用**标签平滑**或**置信度加权**来处理：对来自高信誉谱师的谱面赋予更高权重，或对同一歌曲的多个谱面取平均作为软目标。GOCT在osu!mania上使用社区谱面训练Transformer，证明了社区数据在谱面生成任务中的可行性。

**阶段三：强化学习精调（可选）** 。如果计算资源允许，可以设计“谱面可玩性”奖励函数（如：避免同一时刻超过4个音符同时判定、Hold时长不超过一定阈值），用策略梯度微调。但这一阶段收益不确定，建议在监督学习达到瓶颈后再考虑。

### 5.3 数据增强

**音频端**：音高偏移（±2个半音）、时间拉伸（0.9x-1.1x速度）、添加背景噪声。注意音高偏移会改变音乐的实际音高，如果谱面目标不随音高变化，这相当于增加了任务的噪声鲁棒性训练。

**谱面端**：时间抖动（对音符时间添加±1帧的高斯噪声）、宽度抖动（对音符位置添加±0.02的噪声），这模拟了不同谱师对同一音乐的不同诠释，有助于模型学习更鲁棒的表示。


## 六、效率优化与Infra

### 6.1 Flash Attention

强烈建议在Encoder和Decoder中全面启用Flash Attention。MusicFM的官方实现已原生支持Flash Attention，可通过 `is_flash=True` 参数启用。对于使用HuggingFace transformers加载的MERT，可替换注意力实现为 `attn_implementation="flash_attention_2"`。Flash Attention在长序列（4500+帧）上的内存节省可达50%以上，训练速度提升30%-50%。

### 6.2 混合精度训练

使用bf16混合精度训练。MusicFM在混合精度下仍能保持良好性能，官方建议在特定下游任务（如节拍跟踪）中使用float32以获得更好精度，但谱面生成任务对数值精度的要求低于节拍跟踪，bf16应足够。

### 6.3 优化器选择

**AdamW** 是稳妥的默认选择。**Muon优化器**在LLM和ViT训练中展现出比AdamW更高的收敛效率，值得尝试，但需注意Muon对学习率调度和权重衰减的敏感性较高，可能需要额外的超参数调优。

### 6.4 推理加速

推理阶段可采用动态量化（将线性层量化为int8）或算子融合。对于完整歌曲的谱面生成，建议将音频分块处理（每块30-60秒，重叠10秒），块间通过特征拼接和谱面平滑保证连续性。


## 七、评估指标

谱面生成的质量评估是多维度的，建议采用以下指标组合：

**音符放置精度**：使用F1分数评估预测音符在时间轴上的精确度。这是GOCT和TCP等工作的核心指标。

**音符类型分类准确率**：对正确放置的音符，评估Tap/Hold/Flick/Drag的分类准确率。

**谱面-音乐对齐度**：计算预测音符时间与音乐节拍网格的偏移分布，偏移越小表示对齐越好。

**可玩性指标**：包括同时判定音符数的上限、Hold持续时长的合理性、谱面密度分布与音乐能量分布的相关性。

**人类评估**：最终的金标准仍然是让有经验的Phigros玩家试玩并评分。ChartGenEval提出了六个维度的评估框架，包括音乐契合度和可玩性相关特征，可作为人类评估的参考模板。


## 八、实施路线图

**第一阶段（数据准备）** ：解析Phigros社区谱面，构建音频-谱面配对数据集。使用phichain或py-phi-editor解析谱面文件，将音符事件转换为连续高斯分布张量。

**第二阶段（特征提取）** ：使用MERT-v1-330M提取音频特征，提取第3、6、9、12层隐藏状态的拼接，缓存到磁盘以避免重复计算。

**第三阶段（模型搭建）** ：搭建Encoder-Decoder Transformer，Encoder使用滑动窗口自注意力，Decoder使用完形填空训练策略，输出通道对应音符类型。

**第四阶段（训练）** ：先冻结MERT，仅训练Encoder-Decoder和Adapter。使用BCE主损失+起始点辅助损失。监控验证集上的F1和音符类型准确率。

**第五阶段（后处理）** ：将模型输出的连续高斯分布通过峰值检测（如scipy的find_peaks）和阈值化转化为离散谱面事件，再通过节拍对齐和谱面平滑修正到Phigros可用格式。

**第六阶段（迭代优化）** ：如果性能不足，尝试解冻MERT最后几层进行微调，或引入MuQ作为替代特征提取器进行对比实验。


## 九、关键风险与应对

**特征提取器与任务的不匹配**：MERT是为通用音乐理解设计的，其表示空间可能未充分编码谱面生成所需的“可操作性”信息。应对方案：在特征提取器后接可训练的Adapter，让Adapter学习将通用音乐表示映射到谱面空间；如果效果不佳，可尝试在特征提取器上添加轻量级的任务特定预训练（如谱面事件预测的辅助任务）。

**社区谱面质量不一致**：自制谱面的质量差异可能导致模型学习到不一致的模式。应对方案：建立谱面质量评分机制（基于谱师信誉、谱面定数、社区反馈），在训练中对高质量谱面赋予更高权重。

**推理时的累积误差**：如果采用分块处理，块间的谱面不一致可能导致明显的断裂。应对方案：使用重叠分块和加权平滑，确保块间过渡自然；或尝试一次性处理完整歌曲（配合Flash Attention和稀疏注意力）。
